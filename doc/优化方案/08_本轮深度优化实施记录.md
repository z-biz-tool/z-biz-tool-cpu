## 2. 调查记录

### 2.1 P1 的核心担心不成立：判题与 UI **本来就是同一套**

台账 00 记的是「**没量到** —— `src/challenges/` 7 个文件未通读」，
并列了一句更要紧的：「若判题逻辑只存在于 UI 里，则关卡判题**无法做自动化回归**」。

通读结论：
- 判题入口是 `src/challenges/verify.ts::runLevelTests(level, design)` ——
  **纯函数**，只依赖 `core/sim.ts` 的仿真器，不碰 React、不碰 DOM。
- **编辑器 UI 走的是同一个函数**：`src/editor/store.ts:13` 直接
  `import { runLevelTests } from "../challenges/verify.ts"`。
  ⇒ 不是 UI 里另写一套判题，**P1 的担心不成立**。
- `src/atCoverage.ts` 的 AT-01 验收矩阵（31 关参考解答全过 + 骨架 0 通过）也在用它，
  且 `scripts/verify.ts` 会跑，`ci.yml` 里 `npm run verify` 是一道门禁。

### 2.2 但「同一套」不等于「有回归」—— 判题不在 `npm test` 里

- `npm test` = `node --experimental-strip-types --test tests/*.test.ts`，
  实测 **256 条 / 6 个文件**，而 `tests/` 里**没有一条** import `src/challenges/`。
- ⇒ 开发者本地跑 `npm test`（256 条）**碰不到判题**；判题坏了要等到跑
  `npm run verify` 才发现。而 `verify` 是另一条命令、输出又是另一套口径
  （「内核自检：608 通过」），本地日常根本不会跑。
- ⇒ 本轮把判题**搬进标准测试命令**。

### 2.3 新网抓出的真缺陷：`UNLOCKS` 里的 `t1gates` 死条目

`src/challenges/unlocks.ts` 的 `UNLOCKS` 表里有两条意思相同、写法不同的键：

```ts
t1gates:   ["nand", "not", "and", "or", "xor", "xnor"],   // ← 不是关卡 id
"t1-gates": ["nand", "not", "and", "or", "xor", "xnor"],   // ← 真 id
```

`LEVEL_IDS` 里只有 `t1-gates`，**没有 `t1gates`**（全仓也只有 `unlocks.ts` 这一处用到它）。

后果：**解锁功能看起来是对的，出错的是「解锁来源」那句话**。
- `unlockedTypesFromDone` 逐条 `levelById` 查，查不到就 `continue`
  ⇒ 死条目被**静默跳过**，功能不受影响；
- `unlockSource(type)` 是「按 `UNLOCKS` 的插入顺序取第一个匹配」
  ⇒ `t1gates` 排在 `t1-gates` 前面，于是它返回 **`"t1gates"`**。

`src/editor/Palette.tsx` 拿这个值告诉用户「通过 X 解锁」——
而 **X 这一关根本不存在**，用户照着找会找不到。

⇒ 这正是家族里反复记的那条：**同一套规则在两侧各写一遍必然漂移**。
这里是一张表被两个消费者按**不同口径**读（一个跳过不认识的、一个不跳过），
差异就长成了界面上的一句错话。**已删死条目**。

修前实测：`unlockSource("nand")` → `"t1gates"`；
修后 → `"t1-gates"`。

| 组 | 覆盖 |

### 4.1 变异反向验证

| 变异 | 结果 |
|---|---|
| M1 复活死条目 `t1gates` | 失败 2 条 ✅ |
| M2 判题恒真（`pass = true`） | 失败 1 条 ✅（「裸骨架不能白拿通关」） |
| M3 `unlockSource` 取最后一个匹配 | 失败 1 条 ✅ |

> ⚠️ **本轮第一版变异脚本有 bug**：还原写在 `finally` 里（循环**结束**后），
> 于是 M2 跑的时候 M1 的变异**还在** —— 报出来的「2 条失败」其实是 M1 的，
> **M2 从未被真正验证**。改成「每条变异前先还原」后重跑，
> M2 才暴露出自己**根本没咬住**（因为当时注入的只是加了一行注释 = 语义空操作）。
> 换成真行为变异（`pass = true`）后立刻咬住。
>
> ⇒ 这条与家族记忆里那条同源：**每一轮变异的结果必须逐条归类**，
> 不能只看「总体失败了没有」—— 泄漏的失败会被误记成下一个变异的功劳。
