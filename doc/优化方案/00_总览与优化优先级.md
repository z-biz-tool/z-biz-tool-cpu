## 本仓是什么

数字电路与 CPU 构建沙盒：**从一颗 NAND 门开始，逐级搭到能跑汇编程序的 16 位 CPU**。
纯 TypeScript 内核 + React 画布编辑器，**无后端**、无外部仿真库，全部逻辑自己实现；
内核可在 node 下 headless 运行，判题与自检全走脚本。

- 规模（实测）：前端 ts/tsx **65** 个文件；`src-tauri/src` 只有 2 个文件（Tauri 壳）
- 形态：**纯前端**，`src-tauri` 里 0 个 `#[test]`

## 核心结论：招牌能力零测试，只有汇编器有网

本仓唯一的测试文件是 `tests/assembler.test.ts`，**19 条，全过**
（实测 `npm test` → `tests 19 / pass 19 / fail 0`）。

而这 19 条**全部只测 `src/asm/`（3 个文件）**：

    import { parseNum, assemble, disassemble } from "../src/asm/assembler.ts";

**占代码量最大的部分完全没有测试：**

| 目录 | 文件数 | 内容 | 测试 |
| --- | --- | --- | --- |
| `src/cpu/` | 4 | `netlist.ts`(12KB) / `build.ts` / `custom.ts` —— **门级网表与电路构建** | **0** |
| `src/core/` | 11 | `registry.ts`(**30KB**) / `sim.ts`(**27KB**) / `reference.ts`(**22KB**) / `interpreter.ts` / `serialize.ts` / `recovery.ts` / `trace.ts` … | **0** |
| `src/asm/` | 3 | 汇编 / 反汇编 | **19 条** ✅ |
| `src/editor/` | 20 | 画布编辑器 | **0** |
| `src/challenges/` | 7 | 关卡 | **0** |

`src/cpu/` + `src/core/` 合计 **158.2 KB**（`cat src/cpu/*.ts src/core/*.ts | wc -c`），
是本仓最复杂也最核心的部分，**测试数为 0**。

**这为什么严重**：注意本仓作者自己在 `assembler.test.ts` 开头用的正是这套标准 ——
「汇编器错了是**静默**的 …… 不会抛错」。同一把尺子量 `core/`：
**CPU 执行错了同样不抛错** —— 门级仿真跑出错的电路、`sim.ts` 算出错的波形、
`reference.ts` 的参考实现与真机不一致，用户看到的是"电路不工作 / 波形不对"，
**没有任何东西会报警**。这类 bug 只能靠人肉发现，而人肉发现周期以周计。

即：本仓已经**说对了标准**，只是**没有把它用在自己最核心的代码上**。

## P0 —— 给 `core/` 的仿真与解释器建测试网

### P0-1 ✅ 已完成（2026-10-04）：`src/cpu/interpreter.ts`

测试 **19 → 45 条**，并**查出三个真 bug**（都是补测试时查出来的，不是读代码读出的）：

| # | Bug | 症状 | 修法 |
| --- | --- | --- | --- |
| 1 | 解释器**读不回自己写的值** | `LDA` 读 `program` 而 `STA` 写 `mem`，于是同一条程序的结果**取决于调用方有没有传 program 数组**：`runToHalt(state, program)` 得 0、`runToHalt(state)` 得 123 | 新增 `fetchWord()`：**mem 优先、program 兜底**；`LDI` 读立即数处同样的不对称一并收口 |
| 2 | **PUSH/POP 不配对** | 值压在 SP−1，POP 却读 (SP−1)+1，错开一格。`push r0(55); pop r1` 得 **0**，且 `mem[0xff]` 从未被写过 | 改为「先读当前 SP，再自增」 |
| 3 | 撞步数上限**不留痕** | `runToHalt` 静默返回，调用方分不清「跑完了」和「我放弃了」 | 显式写 `state.fault`（不改 `halted`） |

**Bug 1 尤其要紧**：本仓头注释说这个解释器用于「差分验证」——
拿一个读不回自己存储的解释器去比对电路实现，差分出来的差异
**分不清是电路错还是解释器错**。

变异验证：4 个注入点（POP 退回旧写法 / LDA 退回 program 优先 / 删掉 fault 留痕 /
SHR 改有符号右移）**全部第一次跑就红**。

### P0-2 ✅ 已完成（2026-10-04）：`sim` ↔ `reference` 电路一致性

新增 `tests/cpu-consistency.test.ts`，测试 **45 → 59 条**。

- **做法**：同一个程序分别跑**门级电路**（`referenceCpu` + `Simulator`，
  90 个元件逐拍推进）与**参考解释器**，对账八个寄存器。
- **为什么值得**：两套是**独立实现**，共享的只有 `isa.ts` 的常量，
  所以「两边算出同一个结果」很难由同一个错误同时污染 ——
  单侧断言抓不到"两边一起错"的那种 bug。

变异验证（两个注入点**第一次跑就红**）：

| 变异 | 结果 |
| --- | --- |
| 电路侧 R2 写使能接错到 R1（寄存器串线） | ❌ **11 条红** |
| 共享的 `OP.NOT` 0x8 → 0x9 | ❌ **4 条红** |

⚠️ **第二个变异推翻了我原先写在注释里的断言**。我曾写「共享 ISA 常量被改时
一致性抓不到，因为两边会一起错」—— 实测抓到 4 条，因为**电路侧另有硬编码的
译码位**，不跟着 ISA 常量走。**写「这条测试抓不到什么」时同样要拿变异验证，
不能靠推理。**

**本项也暴露了测试自身的一个失效模式并已修掉**：第一版用
`valueOf({comp, pin})` 取值而**引脚名写错**，三个断言全拿到 `undefined`，
而 `undefined === undefined` 被判成"一致"—— **全绿，电路其实一点没跑**。
现已改用 `probes()`，并在比对前先断言两侧都取到了 number，另加两条
「防自欺」用例把这一点固化。

**一处没做**：电路侧终端输出走 OUT 元件的 print 日志、不落 RAM，
怎么读那条日志本轮没查清，故 OUT 用例只对账寄存器。
**写一条取不到值却恒过的断言，比不写更坏。**

| 轮次 | 新增 | 条数 | 查出 |
| --- | --- | --- | --- |
| 第 1 轮 | `tests/registry.test.ts` | 19 → **53** | `parseWordToken` 用 `parseInt` **静默截断**（`0b12`→1、`0x1g`→1） |

**修掉的三个真缺陷**（均先写断言验红、再改实现、再变异验红）：

1. **ALU op=6（左移）的 carry 取错位**。原写 `(a >>> (bits - sh)) & 1`：
   `sh=1` 碰巧对，`sh>=2` 取到更低的位；`sh>bits` 时 `bits-sh` 为负，
   JS 的 `>>>` 按 32 取模后读到完全无关的位（实测 8 位 `a=0x80` 左移 8 位报 0）。
   左移移出的是最高 `sh` 位，**最后移出的恒是最高位**，与 `sh` 无关。
   这不是死代码：`src/cpu/reference.ts:443` 把 alu 的 carry 并进了标志寄存器，
   错了是 `shl` 指令的 C 标志错。
2. **`shift` 算术右移不掩码**。左移和逻辑右移两个分支都写了 `& m`，
   只有算术右移没有，把 `toSignedLocal` 的**负数**直接交给 `c.w`。
   而 `c.w` 是按**网络宽度**掩的（`netlist.ts:287`：网络宽度取相连引脚的最大值），
   8 位 shift 接到一条同时挂着 16 位引脚的网络上时不会被收窄，
   线上留下 `0xFFC0` 而不是 `0x00C0`。
3. **结构参数未取整**。`serialize.ts:182` 对 `params` 是裸 cast、`import.ts` 不校验，
   `"inputs": 2.7` 能流到 `expandInputs`：引脚循环 `i < n` 取到上界得 3 个引脚，
   而 `cost` 和 `size.h` 保留原值 3.7 —— 同一份数据两套口径。
   改成**先取整、再当缺省处理**（顺序反了会让 `0` 得 4 位而 `0.9` 得 1 位）。

**本项暴露的测试自身失效模式（都已修）**：

- **harness 的 `w` 不按引脚宽掩码** → `shift` 算术右移在测试里是 -64、
  在真实仿真里是 192，同一个元件两套数，5 条断言齐假红。
  而补上掩码之后又走向另一头：`maskWrites` 默认开时**把 eval 自己那层掩码盖住了**，
  于是「去掉 `& m`」的变异跑出来 0 红。最终形态是两种模式都留，
  专设一组「eval 自己掩码」用例关掉 sim 的掩码来测。
- **一条测试名在说谎**：原写「mux：sel 按 sel 宽度取模，高位不参与选路」，
  实际喂的 `sel=1` 在宽度内，**什么都没测**。改名并补超宽 `sel` 的样本后才咬住。
- **只看 `dout` 看不穿内存装载的三件事**（掩码 / 深度 / 缓存键），
  因为读出时还有一层掩码兜着 ⇒ 补白盒用例直接读 `c.s._mem`。

⚠️ **一个被判为「设计选择」因而没有改的地方**：`sel` 超出输入数时
`mux` 夹到最后一路、`demux` 全输出 0，两边**不对称**。
这会改变已有电路的行为，属架构决策而非缺陷，已在用例里钉住并注明。

变异验证：**26 个注入点，第一次跑全部咬住**（第一轮 7 个没咬住，
逐条查清全部是「样本没覆盖到那行代码」而非判据松，**换样本补断言，不放松判据**）。

## 三个 ISA 事实（补测试时量出来的，已写进用例注释）

1. **SHL/SHR 的移位量取自寄存器 B**（`regs[dec.b] & 15`），不是立即数。
   写 `shr r0, 2` 的含义是「按 R2 的值移位」。
2. **Z16 没有条件跳转** —— OP 表里只有无条件 `JMP`，`CMP` 只写标志、
   供电路侧 COND 信号用。所以「循环到 N 就跳出」在 Z16 上**写不出来**。
3. 栈是**递减栈**，且 **SP 初值 0 与程序映像首地址重叠**：
   单次往返正常，但栈越深越往程序区踩。
