### A2 ⚠️ 这 19 条**全部**只测 `src/asm/`

- **量法**：`grep -oE "from \"[^\"]+\"" tests/assembler.test.ts | sort -u`
- 实测唯一一条项目内 import：

      import { parseNum, assemble, disassemble } from "../src/asm/assembler.ts";

- 覆盖面拆开看（`grep -oE "test\(['\"][^'\"]+"`）：
  - `parseNum` 3 条：进制前缀 / 下划线与空白 / 解析失败退化成 0 而非 NaN
  - `assemble` 11 条：字长、注释空行、标签解析、前向引用、base 偏移、
    表达式、未知指令带行号、立即数超 16 位、未定义标签报错、空程序报错、
    多错误一次性报全
  - `disassemble` 5 条：还原文本、地址集合、往返重汇编同机器码、空输入
- **判读：汇编这一层测得相当扎实**（连"空程序要报错而不是静默产出空机器码"
  这种负向用例都有）。

### A4 ⚠️ 为什么这条是 P0（"静默失败"判据）

- 本仓作者在 `assembler.test.ts` 开头写的判据**本身是对的**：
  「汇编器错了是**静默**的 —— 错的机器码照样能跑，只是跑出别的程序，不会抛错。
  没有测试时这类 bug 只能靠人肉发现。」
- 同一把尺子量 `core/`：**CPU 执行错了同样不抛错**。
  门级仿真跑出错电路、`sim.ts` 算错波形、`reference.ts` 参考实现与真机不一致 ——
  用户看到的是"电路不工作 / 波形不对"，没有任何东西报警。
- **即：本仓已经说对了标准，只是没把标准用在自己最核心的代码上。**
