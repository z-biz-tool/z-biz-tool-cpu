# 02 · 问题暴露：从裸机程序到 OS，以及引导（彻底版）

> 上一篇：机器靠 4 条通道协作，裸机能跑你的代码。
> 本篇：给裸机程序加真实需求 → 问题爆炸 → 看每个问题如何孕育一个 OS 设计 → OS 怎么把自己装进机器。
> 彻底版：每个问题都给出可复现的失败场景（代码级），每个答案都补足机制细节——它们就是 mini_machine 05 "OS 前夜"表格的完整展开。

## 1. 需求升级，问题爆炸

hello world 不占资源。我们写个"记事本"：从磁盘读文档 → 显示 → 响应键盘 → 编辑 → 写回。顺便再跑个时钟小工具。问题逐个出现——**每一个都用代码演示它怎么发生**。

### P1：键盘谁来听？

程序正忙着渲染一行（可能几十毫秒），你在敲键盘：

```c
for (;;) {
    render_paragraph();      // 20ms，期间没人看键盘
    if (key_pressed())       // 等回来才查一次
        handle_key();
}
```

20ms 里按下的每个键都丢了——键盘控制器的 RX 缓冲就 1 字节，后来的把先前的顶掉。
**答案**：不能靠程序"有空时查"，必须有个机制随时打断它、把字符先存起来：

1. 键盘中断 handler 只做一件事：把字符放进环形缓冲区（几 μs 完事）
2. 程序有空时来缓冲区取——**生产者（中断）/消费者（程序）**模型

→ **中断驱动的输入缓冲 + 一段常驻的公共代码**。mini_machine 04 的中断版 echo 已经是这个答案的最小原型。

### P2：两个程序都要 CPU

想同时跑记事本 + 时钟小工具，CPU 只有一个。朴素方案——手工交接：

```c
// 记事本里手工插入：
if (tick_flag) { tick_flag = 0; clock_task(); }   // 每隔一阵切去跑时钟
// 时钟任务里再手工切回来……
```

两个程序得互相知道对方的存在、位置、每个旗标变量——写第三个程序就要重排所有交接点，第 N 个程序时交接代码爆炸。
**答案**：需要一个中立的第三方**强制**切换，交接点固定且与程序无关：时钟中断（定时响铃，谁也关不掉）+ 常驻内存的处理代码——铃一响，硬件自动跳进"切分"代码，不管正在跑的是谁。这就是**调度器的种子**。被切换的程序互相不认识、不需要认识——"进程"概念在此发芽（03 篇展开）。

### P3：程序放在内存哪里？

记事本假设自己从 `0x1000` 开始（链接时定死，01a 篇②），时钟也想从 `0x1000` 开始 → 后加载的覆盖先加载的。手动约定不同地址？程序一改动大小，全盘重排所有链接地址。
**答案**：让每个程序都以为自己独占从固定地址开始的内存，运行时再翻译：

```
记事本虚拟地址 0x1000 → MMU 查页表 → 物理地址 0x03000
时钟   虚拟地址 0x1000 → MMU 查页表 → 物理地址 0x12000
```

MMU 是 CPU 里的一块翻译电路：每次访存先查页表（页号 → 物理帧号），程序只发虚拟地址。**同一个人人喊打的"地址撞车"问题，翻译层一挡就消失** → **地址翻译（MMU + 页表）的种子**（04 篇展开）。

### P4：一个程序的 bug 毁掉一切

时钟程序有个野指针 `int *p = (int*)0x3000; *p = 0;`——如果 0x3000 恰好落在磁盘引导扇区的缓冲上，你的文档没了；如果落在记事本的代码上，它行为错乱而且**无法定位**（没有报错，只有诡异的错乱）。
**答案**：访问要过检。硬件提供两件武器：

- **特权级（ring 0/3）**：页表项上有"谁可以访问"的权限位；CPU 也有当前特权级（CPL）。ring 3 的程序写内核页 → CPU 硬件当场拒绝并触发缺页异常（也是一次中断！）
- **页表权限位**：每页可标 只读/不可执行/内核专用

**注意关键处：检查是硬件做的**——软件检查可以被绕过（bug 总在检查代码里），硬件检查不可绕过。从此"危险操作"必须委托给一个更可信的层 → **特权级（ring 0/3）+ 页表权限位**的种子。

### P5：每个程序都自带一份驱动

读磁盘需要精确的时序协议（写命令寄存器 0x1F2=扇区数 → 0x1F3~6=LBA → 0x1F7=读命令 → 轮询状态 → 逐字搬 DR）。每个程序都抄一份？两重灾难：代码 ×N；任何一个程序的 bug 写坏全盘数据（它有完整的磁盘写能力）。
**答案**：碰硬件的代码只留一份（在常驻层里），程序只能提出"请求"（读第几扇区），由常驻层代为执行 → **驱动 + "一切皆文件"的雏形**（05 篇展开）。

### P6：数据没有名字

文档存在"扇区 1024 起，共 37 扇区"——人没法用，程序之间也没法交换（你的记事本存的位置，别的编辑器不知道）。
**答案**：名字 → 位置的映射层。存一份目录表：`"note.txt" → (扇区1024, 37扇区)`。目录本身也要有名字、也要占扇区、也能删改——**递归上桌** → **文件系统**（05 篇展开）。

### P7：等磁盘时 CPU 空转

读一个扇区要几十毫秒（memory_work 04：寻道+旋转），CPU 轮询状态口：

```c
out(0x1F7, CMD_READ);
while (!(in(0x1F7) & ST_BSY)) ;   // ← CPU 在这里空转 10ms = 十万条无用指令
```
**答案**：发起读之后去跑别的（切给时钟小工具），数据到了（磁盘中断）再回来 → **阻塞/唤醒机制的种子**（03 篇展开）。

## 2. 所有答案同一个形状

把七个答案排在一起看：

| 问题 | 答案 |
|---|---|
| P1 输入丢失 | 常驻代码 + 中断缓冲 |
| P2 争抢 CPU | 常驻代码 + 时钟中断强制切换 |
| P3 地址冲突 | 常驻代码 + 页表 |
| P4 越界破坏 | 常驻代码 + 特权级 + 权限位 |
| P5 驱动重复 | 常驻代码 + 统一请求入口 |
| P6 数据无名 | 常驻代码 + 名字映射表 |
| P7 空转等待 | 常驻代码 + 睡眠队列 |

**形状完全一样：一层常驻内存的公共代码 + 对外统一的请求入口。**

这层公共代码就叫**内核**。它对程序的请求入口叫**系统调用（syscall）**，对设备的请求入口叫**中断向量表（IDT）**。注意这两个入口的对称性：

```
        程序 --syscall(按铃:我请求服务)--> 内核 <--中断(按铃:我干完了/有事)-- 设备
                    同一层代码，两个方向的门铃
```

> OS 不是设计出来的怪异产物，是七个问题收敛出的必然形状。读内核源码或书时，永远先问："这在解决 P 几？"——mini_machine 05 的"OS 前夜"表就是这七个问题在单片机上的最小版本。

## 3. 引导：OS 怎么把自己装进机器（鸡生蛋问题）

OS 自己也是磁盘上的一个文件。但它要管理的所有东西（页表、中断表、调度器）在它跑起来之前都不存在——**它必须亲手把自己脚下的地基建起来**。

### 引导链

```
BIOS/UEFI
  → MBR（512B，GRUB 的第一段；01 篇你写的那段的地位）
  → GRUB：认得文件系统，从磁盘把内核镜像 vmlinuz 读进内存
  → 跳到内核入口点（此刻内核和 01 篇的 hello 一样，跑在裸机环境）
```

为什么要多级引导，BIOS 直接装内核不行吗？**能装的不多**：BIOS 只会读扇区、只认 512B+签名；内核是几 MB 的 ELF、放在 ext4 文件系统里——BIOS 不懂 ext4。GRUB 第一段（进 MBR 的 446 字节）只干一件事：把自己剩下的部分搬进来；GRUB 主体才认得文件系统、能读文件。**每级引导解决"找到下一级"的问题，链条一环扣一环**（01a 篇六环链的放大版）。

### 内核自举（boot 阶段做的事，顺序敏感——每步都有"为什么是现在"）

1. **自己建临时页表并打开分页**（填页表 = 普通写内存，`mov CR3` 激活）
   ——为什么先做：后面一切都要用 C 写大结构体（IDT 256 项、进程结构、缓冲区），而 C 假设"地址随便用"。没有翻译层，代码只能写死物理地址、彼此避让——寸步难行。**这一步的本质：给软件世界先铺一层"地址幻觉"的地基**。
2. **建 GDT / IDT**：GDT 是段描述符表（现代 x86 里基本只剩"我是什么特权级"一个用途）；IDT 是中断描述符表——全机器门铃的接线板，256 个门铃号 → 内核里的处理函数。从此每个中断都有归属。
3. **初始化中断控制器、打开时钟中断**：从这一刻起，内核每秒被叫 N 次（典型 100~1000 次）、强制夺回控制权——P2 的答案上线，调度器从种子长成器官。
4. **探测设备、加载驱动**：扫描总线（PCI 枚举：读每个设备的配置空间问"你是谁"），把对应驱动挂上——P5 的答案上线。
5. **挂载根文件系统（rootfs）**：从这一刻起，"文件"才存在（P6 上线）。之前的一切都是"写死的地址"——内核镜像自己也是被 GRUB 按**扇区**读进来的，还没资格谈文件。
6. **创建 1 号进程（init/systemd）**：内核手工伪造一个进程的账本（03 篇：CPU/内存/IO 三本账），把内核剩下的启动逻辑"变成一个普通程序"交给它——用户态世界的根。此后所有进程都是它的 fork 后代。
7. init 起服务、起登录 → 你敲 `./a.out` → shell 调 fork+exec → 你的程序活在内核搭好的世界里。

### 三个引导期亲手搭起来的关键件

| 结构 | 是什么 | 谁建的 | 何时上线 |
|---|---|---|---|
| IDT | 中断向量表：256 个门铃 → 处理函数的接线板 | 内核自己 `mov` 填表 | 自举第 2 步 |
| 页表 + CR3 | 地址翻译规则（虚拟页 → 物理帧的映射数组） | 内核自己写内存 | 自举第 1 步 |
| syscall 入口 | 内核用 MSR 寄存器把入口地址写给 CPU，此后用户程序一条 `syscall` 指令直达 | 内核初始化时注册 | 初始化后期 |

一个重要细节：**内核的代码和数据被映射在每个进程页表的最高地址段**（x86-64 的 `0xFFFF8000_00000000` 以上）——所以任何时候触发中断/系统调用进内核，都不用换地址空间就能执行内核代码。这是引导期页表设计埋下的伏笔（04 篇展开）。

**鸡生蛋的完整解法在此收口**：内核用"裸机能用的 4 条通道"（01 篇）亲手搭出"内核才能提供的世界"（翻译、特权、文件、进程）——**搭的过程中它自己还是个裸机程序；搭完之后它才配得上"内核"这个名字**。

## 4. 归约检验

问：从通电到 shell，用了哪些根能力？

- BIOS 跳转：改 RIP
- 内核建表：`mov`（写内存）
- 开分页：`mov CR3`
- 配中断控制器/时钟：`out`/`in`
- 一切响应：中断

**全部归约到 4 条通道 + 几条指令，引导没有任何新硬件能力。**

所谓"OS 启动"，就是一段代码用最原始的指令，把自己需要的世界（页表、接线板、时钟、根进程）亲手搭出来。

## 5. 本篇结论

1. **OS 的每个模块对应一个具体问题**；问题不出现，设计就不会出现。七个问题各有代码级失败场景，不是抽象说教。
2. **内核形态 = 常驻公共代码 + 两个统一入口**（syscall 给程序用，IDT 给设备用）——同层代码，两个方向的门铃。
3. **引导 = 内核在裸机环境里自建地基，然后造出第一个用户进程，把世界交给它**；顺序敏感：先页表（给 C 铺地址幻觉）→ 再接线板 → 再开时钟（夺回控制权）→ 再文件 → 再交权。
