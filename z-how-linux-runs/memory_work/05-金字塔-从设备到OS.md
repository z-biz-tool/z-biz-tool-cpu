# memory_work 05 · 金字塔：从设备到 OS（彻底版）

> 前四篇拆完了介质：SRAM/DRAM（01）、Flash（02）、SSD 迷你计算机（03）、磁化机械（04）。
> 本篇把它们放上同一把尺，回答最后一个问题：**为什么必然分层？OS 在这堆设备上到底干了什么？**
> **一句话总纲：金字塔不是设计选择，是"没有任何介质又快又大又便宜"的数学必然；OS = 金字塔的专职搬运公司。**

## 1. 全家福：一张表看穿所有介质

| 层 | 代表 | 访问延迟 | 容量 | $/GB（2024 粗价） | 维持机制（00 篇） |
|---|---|---|---|---|---|
| 寄存器 | SRAM 触发器 | ~0.3 ns | ~1KB | 数万元 | ①正反馈 |
| L1/L2/L3 | SRAM | 1~20 ns | KB~百 MB | 数千~万元 | ①正反馈 |
| 主存 | DRAM | 60~100 ns | 十~百 GB | ~$2-3 | ②薄墙+刷新 |
| 本地持久 | NVMe SSD | 20~100 μs | 0.5~8 TB | ~$0.05-0.1 | ②厚墙 |
| 机械盘 | HDD | 4~10 ms | 4~30 TB | ~$0.01-0.015 | ③磁化 |
| 归档 | 磁带/冷云 | 秒~分钟 | PB 级 | ~$0.002-0.005 | ③磁化 |

读表的三个方法：

1. **纵向看延迟**：每往下跳一层，延迟 ×100~1000（DRAM 100ns → SSD 50μs 是 ×500；SSD → HDD 5ms 是 ×100）。**这一条是硬的**——由物理决定（电平读 vs 电压泵 vs 机械臂），50 年没变过。
2. **纵向看价格**：每往下跳一层，$/GB ÷10~100。**这一条也是硬的**——由密度与工艺决定。
3. **横着没有任何一格又快又便宜**——**金字塔不是谁设计的，是这两个硬约束的乘积形状**。cpu_work 06 的缓存层级（L1→L2→L3→内存）就是这座金字塔顶部的硬件副本。

## 2. 为什么缓存必然有效：局部性原理

金字塔要能工作，必须有个前提：**大部分访问集中在小部分数据上**。两条局部性：

- **时间局部性**：刚访问过的数据很快再被访问（循环变量、热函数）
- **空间局部性**：访问了地址 X，X 附近很快也被访问（数组遍历、顺序代码）

数字演算：假设 L1 命中率 95%、L2 90%、L3 80%、内存 100%（忽略盘）：

```
平均访问时间 = 0.95×1ns + 0.05×(0.9×10ns + 0.1×(0.8×20ns + 0.2×80ns))
            ≈ 0.95 + 0.05×(9 + 0.1×(16+16))
            ≈ 0.95 + 0.05×12.2 ≈ 1.56ns
```

**80ns 的内存被平均成 1.56ns**——金字塔的全部经济学就是这一行算式。局部性哪怕只有中等水平（命中率 90%），收益也是数量级的；**这就是为什么 50 年来所有优化都围绕"提高命中率"而不是"加快下一层"**（memory_work 01 §8：DDR 带宽 ×48 而延迟原地踏步——大家早就放弃了跟物理硬碰）。

## 3. 复制品视角：金字塔上每一层都是下层的缓存

这是本篇最重要的视角转换：**金字塔不是"存东西的地方"，是"同一份数据的不同清晰度副本"**。

- 你正在编辑的这段文字：寄存器里有一份（字节）、L1 里有一份（缓存行）、内存里有一份（page cache 里也有一份！）、SSD 上有一份（文件）、备份盘里还有一份
- **哪份是"真的"？** 全是，也全不是——**SSD 上那份是权威（source of truth），上面的全是复制品**
- 复制品管理 = 缓存一致性问题的全谱系：CPU 内 L1-L3 用 MESI（cpu_work 06）、内存与盘之间用 page cache + fsync（本篇 §5）、数据库与内存用 buffer pool + WAL——**同构 ×3**

**读 = 沿金字塔往上找最近副本；写 = 先改高层副本、择机同步回权威。** 所有一致性/丢失/性能问题的根源都在"择机"两个字上。

## 4. 三层软件栈，同一套缓存思想

| 层 | 缓存 | 命中 | 未命中动作 | 回写 |
|---|---|---|---|---|
| 硬件 | CPU L1/L2/L3 | ~95% | 向下层取（cache line 64B） | MESI 硬件自动 |
| OS | page cache（空闲内存当盘缓存） | 看命中率 | 缺页中断 → 从盘读 4KB | writeback（脏页内核线程定期落盘） |
| 应用 | buffer pool（数据库）/应用缓存 | 看命中率 | 读盘 → 进池 | WAL/checkpoint |

三层各自独立发明了：预读（硬件 prefetch / OS readahead / 数据库 prefetch）、逐出策略（LRU 变体：PLRU / 双链表 LRU / 缓存命中率优化）、脏数据回写。**为什么同一套思想长三次？因为三层的速度鸿沟一样存在（100×量级），局部性原理一样成立**——物理约束相同，软件形态趋同（主系列 02 篇"所有答案同一个形状"的又一例）。

## 5. OS 的角色：金字塔搬运公司

内核的内存子系统 = 金字塔调度台，四项核心业务：

| 业务 | 机制 | 对应介质操作 |
|---|---|---|
| 读加速 | **page cache**：读过的文件页留在内存，再读命中免盘 | DRAM ↔ SSD/HDD |
| 写缓冲 | **dirty page writeback**：写先落内存（立即返回），脏页按策略（脏占比/超时 30s）异步落盘 | 同上 |
| 内存不够 | **swap/换页**：把冷页写进 swap 区，腾出的帧给热页——**内存的延伸层是盘**（LRU 逐出，与 L3 逐出同构！） | DRAM ↔ swap 分区 |
| 按需加载 | **缺页（page fault）**：mmap/execve 只建映射不搬字节，第一次访问触发缺页才真正读盘——01a 篇"甚至可以不真搬字节"的兑现处 | 按需向上搬运 |

两个日常现象的精确解释：

- **fsync 为什么慢**：write() 只是进了 page cache（μs 级返回），fsync 强制穿越金字塔直落 SSD/HDD（μs→ms），并等 ACK——**"强制同步复制品与权威"的价格**
- **free 命令里 buff/cache 占几个 GB 不是浪费**：空闲 DRAM 不当 page cache 才是浪费（读一次就快一次）；需要时立即可回收——**金字塔的每一层都该被填满，包括顶层**

## 6. 展望：金字塔的新楼层

| 技术 | 是什么 | 补的空档 |
|---|---|---|
| CXL | 缓存一致性互联（PCIe 上的内存语义协议） | DRAM 池化/扩展：多机共享内存条，内存也能"插"在机箱外 |
| 持久内存残留思想 | 字节寻址 + 非易失（Optane 思想，03 篇） | 金字塔"内存层"与"持久层"的合并幻想——输给价格但思想在 CXL/大容量 AEP 场景残留 |
| HBM | 3D 堆叠 DRAM 与 GPU 同封装 | GPU 的"最接近的下一层"——带宽 1TB/s+，印证"越近越快"不变的物理 |
| zNS/ZNS SSD | 按 zone 顺序写的 NVMe | 把 03 篇 FTL 的搬家成本**显式交给文件系统**——FTL 变薄，上层自己顺序化 |

**金字塔在长高、变宽，但形状逻辑不变**：每一层用上一层的局部性，赚 100× 的物理差价。

## 8. 本篇结论

1. **金字塔 = 两个硬约束的乘积形状**：延迟每层 ×100~1000、价格每层 ÷10~100，没有全赢介质——分层是数学必然，不是设计品味。
2. **缓存有效靠局部性**：中等的命中率（90%+）就能把下一层 100× 的慢平均掉——50 年优化的主战场从来是命中率。
3. **复制品视角**：权威在底层，上层全是副本；读=找最近副本，写=改副本择机同步——一致性问题全谱系（MESI/page cache/WAL）同构。
4. **三层软件栈同一套缓存思想**：预读/逐出/回写在硬件、OS、应用各长一次——物理约束相同则软件形态趋同。
5. **OS = 金字塔搬运公司**：page cache、writeback、swap、缺页——四项业务全部是"沿金字塔搬副本"；fsync = 强制穿越的价格。
6. 楼层在更新（CXL/HBM/ZNS），**形状逻辑永不变**。
