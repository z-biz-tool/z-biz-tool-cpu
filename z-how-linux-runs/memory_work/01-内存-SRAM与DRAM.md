# memory_work 01 · 内存：SRAM 与 DRAM（彻底版）

> 00 篇的两种"电"维持机制在内存里正面相遇：SRAM（正反馈锁定）与 DRAM（电荷囚禁）。
> 本篇从一颗 cell 的毫伏级物理，一路讲到内存条上的第 9 颗芯片——**每一个时序参数、每一根金手指、每一次刷新，全部给出出处。**

## 1. SRAM：6T 单元的完整物理

### 1.1 两个稳定点从哪来：电压传输曲线的"蝴蝶图"

6T 单元 = 两个交叉耦合反相器（4 管）+ 2 个存取管。把两条反相器的电压传输曲线（VTC）画在同一张图上（一条横放），得到"蝴蝶图"：

```
Vout1 │  ╲              ╱
      │   ╲            ╱
      │    ╲          ╱     ← 两条曲线三个交点：
      │     ╲        ╱        左右两个是稳定点（0/1）
      │      ╲      ╱         中间那个是不稳定点
      └──────────────────── Vout2
         稳定态A  翻转点  稳定态B
```

中间交点处两管同时半开、增益 >1，任何微小偏移都被反相器放大推走——这就是"稳定"的电路学定义：**扰动被负增益吃掉**。两条曲线越"胖"，稳定越牢（保持裕度 hold margin）。

### 1.2 读操作的毫伏级分解（以及为什么读会毁单元）

1. 位线 BL/BL̄ 预充电到 VDD/2（差分：两条线对称拉平）
2. 字线 WL 拉高，存取管打开
3. 存 1 的一侧（内部节点=VDD）经存取管把 BL 往上顶，另一侧往下拉——**只是充放 BL 的一点点寄生电容**，ΔV ~100 mV 量级
4. 差分感放识别这个 ΔV，放大成满幅

风险：**读也会翻转单元（read upset）**——BL 上 VDD/2 的电压会反向灌进内部节点，如果存取管相对驱动管太强，单元被"读翻"。设计约束（cell ratio）：内部驱动管必须显著强于存取管——晶体管尺寸是拿裕度换的，这是 SRAM 版图设计的第一课。

### 1.3 写操作：以强凌弱

写 = 把 BL/BL̄ 一条强拉到 GND、一条强拉到 VDD，**强行越过翻转点**。要求写管（存取管）足够强能压过内部反相器——**与读的要求正好相反**（读要存取管弱，写要存取管强）。现代 SRAM 用"读辅助/写辅助"电路（动态调 VDD、调字线电压）同时保住两个裕度——28nm 之后这是良率生死线。

### 1.4 多端口的代价：为什么寄存器只有几十个

cpu_work 05 篇的寄存器堆要 2 读 1 写三端口。SRAM 每加一个读口 = 每单元再加 2 个存取管 + 位线——**面积近似线性×端口数，且位线电容翻倍拖慢速度**。32 个寄存器 × 3 端口 × 32 位就是寄存器堆面积 / 时序预算的天花板——这就是 x86 只有 16 个架构寄存器、RISC-V 定 32 个、而乱序核靠几百个物理寄存器（重命名，cpu_work 06）绕开这堵墙的原因。

### 1.5 岗位表

| 位置 | 位规模 | 为什么是 SRAM |
|---|---|---|
| 寄存器堆 | 数 KB | 多端口 + 单周期 |
| L1/L2/L3 | KB~百 MB | 速度；L3 部分开始用低密度优化 |
| TLB | 数千项 | 相联查找（内容寻址） |
| 感放/row buffer（DRAM 内） | 每行 | 见第 3 节 |

## 2. DRAM cell：一颗电容的物理学

### 2.1 电容的两种做法：地下 vs 高楼

- **沟槽电容（trench， DRAM 时代早期主流）**：在硅里刻深井，井壁做电极——电容"藏"在晶体管下方
- **堆叠电容（stacked，现代主流）**：晶体管做平，电容像楼一样**摞在晶体管上方**（柱状/瓶状，高宽比 ~30:1）

**注意：DRAM 早就 3D 化了**（堆叠电容几十年）——02 篇 NAND 的 3D 化不是首创，是回到老路。

### 2.2 刷新预算的数学：64 ms 怎么算出来的

- 单元电容 C ≈ 25-30 fF，存"1" ≈ 3~4 万个电子
- 允许的漏电损耗：约一半电荷（感放能分辨的极限）
- 关断存取管的亚阈值漏电 + 结漏电：fA 量级/单元
- 算账：3 万电子 ÷ 一半 ≈ 1.5 万电子 ≈ 2.4 fC；按 fA 级漏率 → 半衰期几百 ms，**留 10 倍安全余量 → 64 ms**（JEDEC 标准；高温 85°C 以上规格翻倍刷新率——温度越低漏电越慢，超频玩家给内存散热不是玄学）

### 2.3 电荷共享的数字演算（为什么感放是必需品）

位线挂 ~1024 个单元，寄生电容 C_BL ≈ 10×C_cell：

```
预充电：V_BL = VDD/2（天平调零）
选通后：V' = (C_cell·V_cell + C_BL·V_BL) / (C_cell + C_BL)
VDD = 1.2V，存满：V' ≈ (30fF×1.2 + 300fF×0.6) / 330fF ≈ 0.6545V
→ ΔV ≈ ±54 mV ——这就是感放要抓的信号
```

感放（一对交叉耦合反相器，00 篇机制①）抓住 54 mV，一端拉满幅——**同时把单元电荷补回**（回写）。位线为什么要预充电到 VDD/2：让"读 0"和"读 1"的摆幅对称，感放两边公平。

## 3. 从 cell 到芯片：完整层级与命令协议

### 3.1 die 内的层级

```
cell（1T1C）
 └─ 感放组（每 512~1024 bit 一组，两侧对夹）= row buffer 的一段
     └─ mat / subarray（一次能同时激活的独立子阵）
         └─ bank（独立阵列，可并行工作；DDR4 每 die 16 bank，分 4 个 bank group）
             └─ die（一颗 DRAM 芯片，8Gb=2^33 bits）
                 └─ package（你内存条上看到的一颗颗粒，可能叠 2~8 层 die）
```

### 3.2 命令协议：内存不是"按地址取货"，是"接命令单"

内存总线没有纯地址读——控制器发的是**命令序列**（命令与地址复用同一组引脚）：

| 命令 | 全称 | 动作 |
|---|---|---|
| **ACTIVATE (ACT)** | 行激活 | 行地址译码，整行 8192 bit 涌进感放阵列（row buffer） |
| **READ / WRITE** | 列操作 | 列地址从 row buffer 选列，burst 8（一拍数据打 8 个节拍） |
| **PRECHARGE (PRE)** | 预充电 | 关闭当前行，位线回到 VDD/2，准备开下一行 |
| **REF** | 刷新 | 对所有行做内部"读-回写"；或逐 bank 刷新（DDR4 Per-Bank Refresh） |
| **MRS** | 模式寄存器设置 | 配 CL、burst 长度等（内存条训练时干的事） |

### 3.3 一次读的完整时序（ns 级推演，DDR4-3200，CK=1600MHz，tCK=0.625ns）

```
ACT  → tRCD=16(tCK)≈10ns  → READ → CL=22(tCK)≈13.75ns → 数据出现（burst 8 连打 8 拍）
         ↑激活一行                            ↑列选通到数据上总线
换行的话：PRE(tRP=16≈10ns) 再 ACT
```

- Row hit：~14 ns（仅 CL + 传输）
- Row miss：~24 ns（+tRCD）
- Row conflict：~34 ns（+tRP +tRCD）

**加上 MC 内部排队、MMU/TLB、总线往返，应用看到的 ~70-100 ns 就是这么叠出来的。** 内存的"慢"= 激活税 + 排队 + 往返，每一项都点名可查。

### 3.4 并行结构的意义

- **Bank**：多阵列独立接客（bank A 在刷新，bank B 照常读写）→ 控制器把请求散到不同 bank 流水
- **Bank group**：DDR4 引入，同组内连发 tCCD 长、跨组短——交错发更有吞吐
- **Rank**：8 颗 x8 颗粒同进同出 = 64 位位宽（数据总线一拍传 8 字节）
- **Channel**：MC 独立总线，双通道 = 两条 64 位并行

## 4. 从芯片到内存条：DIMM 的物理

### 4.1 内存条上有什么

一块 8GB DDR4 UDIMM：

- **8 颗 DRAM 颗粒**（x8 各供 1 字节，组成 64 位 rank）
- **1 颗 SPD EEPROM**（256 字节小芯片，焊在金手指旁）
- 金手指 288 pin：数据 64 + 佳 ECC 无则 0 + 地址/命令 ~20 + 时钟/使能/电源/接地

### 4.2 SPD：内存条的"自述文件"

SPD 里烧录着 JEDEC 规格表：颗粒厂商、代数、容量组织、**全套安全时序（JEDEC 标准档，保守）**、时序许可表。BIOS 上电读 SPD 按保守档跑——**这就是"标称 3200 的条子默认 2133"的原因**。XMP/EXPO = 厂商把超频档也写进 SPD 扩展区，BIOS 读到后敢跑 3200+。**内存条自己带着自己的说明书。**

### 4.3 ECC 内存：第 9 颗芯片

ECC DIMM = x8 颗粒 9 颗（64+8=72 位位宽）。纠错由 MC 完成（见第 7 节）。服务器离不开它的原因见 7.1：**32GB 内存一周内必遭软错误**。

### 4.4 RDIMM / LRDIMM：信号完整性与容量

- UDIMM：MC 直连每颗颗粒，2 条/通道是极限（信号反射）
- **RDIMM**：地址/命令经寄存器缓冲再分发——MC 只面对"一个负载"，信号干净，可插更多条
- **LRDIMM**：连数据也缓冲，把 rank 化整为零——单条 128GB+ 的唯一路
- 走线拓扑：地址/命令用 **fly-by**（一串串过去，各颗粒收到时钟有时间差）→ MC 靠 **write leveling** 逐颗粒校准写偏移——**内存"训练"就是开机头几百毫秒干的事**

### 4.5 插槽规则

- 双通道主板两条内存**插同色插槽**（各占一通道）；单插一条 = 半带宽
- 同条 2R 比 1R 好：两个 rank 交错（一个在 PRE，另一个可 READ）——流水掩盖时序
- 四通道平台插满才有全带宽

## 5. 内存控制器：真正的指挥官

MC 在 CPU 里（2008 年 Nehalem 把它从北桥搬进 CPU——内存延迟立减 ~30ns，因为少过一道芯片）：

| 职责 | 干什么 |
|---|---|
| 地址映射 | 物理地址 → (channel, rank, bank group, bank, row, col) 的散列——**故意把连续地址打散**，让顺序访问摊到多 bank 并行，避免全撞同一个 bank |
| 请求调度 | FR-FCFS：先来先服务 + **行命中优先**（重排队列最大化 row hit，01 篇的"电梯思想"） |
| 读/写分离 | 读和写切换总线方向要代价（tWTR/tWTR_L），攒批读写再切 |
| 刷新调度 | 把 REF 撒进空闲窗口，避免正好撞上重负载 |
| 写合并 | 多次小写合并成整 burst |
| QoS | 实时流量（显示输出）优先于大带宽流量（memcpy） |

## 6. 刷新的两种姿势

- **自动刷新（auto-refresh）**：MC 定期发 REF，8Gb 颗粒单次 tRFC=350ns，分摊下来平均每 ~3.9μs 一次（8192 行 / 64ms）——**占用带宽 ~3-5%**
- **自刷新（self-refresh）**：S3 睡眠（内存供电保留、CPU 断电）时，DRAM 靠内部自振时钟自己刷自己——**内存条的"独立生存能力"**，你的电脑睡眠一晚醒来数据还在，就是它在值夜班

## 7. 可靠性：从宇宙射线到 Rowhammer

### 7.1 软错误：粒子物理决定的故障率

高能中子（宇宙射线secondary）与封装材料 α 粒子击穿 cell 或位线 → 电荷瞬间改写。每 GB 每小时错误率 ~1e-4~1e-3 量级——**32 GB 服务器一昼夜必中数次**。不是玄学，是海拔（高原数据中心错误率更高）和封装材料（含铅焊料时代更糟）的函数。

### 7.2 SECDED 汉明码实例：72 位怎么长出来的

64 位数据 + 8 位校验，按 Hamming 规则摆放（位置为 2^k 的位是校验位）：

- 8 个校验位 p1,p2,p4,…,p256，每个负责"地址含该二进制位"的数据位
- 读出时重算 syndrome（症状字）：**syndrome=0 无错；非零=出错位的位置编号 → 翻转即纠**（纠 1 位）；全零校验但不匹配 = 检出 2 位错（SECDED：Single Error Correct, Double Error Detect）→ 机器检错（machine check）
- **代价仅 12.5% 冗余，换来硬件级自动纠错**——DRAM 用不起更强码，更强码在 SSD（LDPC）。

### 7.3 Chipkill：一颗颗粒整死也扛住

x8 颗粒雷击/焊点断裂 = 同 burst 的 8 位齐坏，SECDED 不够。Chipkill 把一个 64 位字的数据**拆散到多颗颗粒**（类似 RAID 条带），任一颗粒全灭也能用其余恢复——服务器标配的"RAID 1 for memory"。

### 7.4 Rowhammer：刷新防线的合法外攻击

2 个 bank 里反复 ACT 两个"hammer 行"（16 万次/ms 级），行间耦合噪声让**相邻行**电荷加速泄漏 → 位翻转。刷新按"正常泄漏"设计，挡不住这种蓄意轰炸。防线：TRR（Target Row Refresh，MC 记仇、多刷受害邻行）、更大间距、ECC 兜底——**但 ECC 也不绝对（ECCploit）**。密度越高越容易 hammer：这是 DRAM 缩小的安全税。

## 8. 内存墙的完整数字账

| 代 | 频率 | 带宽/通道 | 随机延迟(ns) |
|---|---|---|---|
| SDR-133 | 133 MT/s | 1.06 GB/s | ~110 |
| DDR-400 | 400 | 3.2 | ~95 |
| DDR3-1600 | 1600 | 12.8 | ~75 |
| DDR4-3200 | 3200 | 25.6 | ~62 |
| DDR5-6400 | 6400 | 51.2 | ~58（板载 DAC/on-die ECC 另论） |

**带宽 ×48，延迟仅 ÷2**——延迟被 tRCD（激活）与电容物理钉死。cpu_work 06 篇"CPU 等 200 拍"的完整答案：**DDR 的进化史是带宽史，不是延迟史；等不起的那部分靠缓存与并行掩盖。**

## 9. 本篇结论

1. **SRAM 的稳定是电路学定义**：VTC 蝴蝶图的稳定交点；读写裕度互相矛盾（读要存取管弱、写要强），先进工艺靠辅助电路保良率；多端口面积平方级 → 寄存器数量是设计出来的稀缺品。
2. **DRAM 一切怪癖出自 1T1C**：64 ms 刷新是"3 万电子 ÷ fA 级漏电 ÷ 安全余量"的算术；54 mV 的电荷共享决定感放是刚需；row buffer 决定 hit/miss/conflict 三档延迟。
3. **内存是命令总线不是地址总线**：ACT/READ/PRE/REF 序列 + burst；应用看到的 70-100 ns = 激活税+排队+往返的逐项叠加。
4. **DIMM 是一台小系统**：SPD 自述文件、ECC 第 9 颗芯片、RDIMM 缓冲、fly-by 训练——"内存条"三个字下藏着这些机构。
5. **MC 是指挥官**：地址散列、行命中调度、读写分批、刷新藏闲时——同样一套"最大化物理连续性"的调度思想。
6. **可靠性是买来的**：SECDED 12.5% 冗余、Chipkill 条带化、TRR 防锤——对着粒子物理与恶意攻击分别上保险。
