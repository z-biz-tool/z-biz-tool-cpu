# cpu_work 05 · 合体：译码器与第一颗 CPU（彻底版）

> 零件齐了：门（02）、加法器（03）、触发器（04）。本篇彻底版：先用译码器/MUX 补齐两个积木，然后一砖不差地砌出 CPU——RISC-V 最小指令集逐字段、数据通路逐指令走查、控制信号全表，最后三个被按下的进化点（三态总线、微程序、中断/栈）。

## 1. 补齐两块积木：译码器与 MUX

**译码器（decoder）**：n 位输入 → 2ⁿ 根输出线，恰好一根为 1——"地址点名器"：

```
输入 10 ──[译码器]── 2⁴=16 根线：0000000000000100（第 2 根亮）
```

用途：寄存器堆选行（5 位 → 32 根字线）、内存选 bank/row（memory_work 01）、mini_machine 01 的地址译码。**"编号 → 独占使能"是它的一切**。

**多路选择器（MUX）**：译码器的反向——n 位选择码，从 2ⁿ 路输入里放行一路：

```
sel=01 ──┐
in0 ────[MUX]──── out
in1 ────┘  in2…   （sel=01 → out=in1）
```

用途：ALU 的"这拍做加法还是做与"（结果二选一）、写回寄存器选数据源、**分支目标二选一**。**译码器分发、MUX 收拢——数字电路的左右手**。

## 2. 指令集：先定契约再砌砖

CPU 是"取指-执行"机（主系列 01 篇）——但执行什么、怎么编码，得先签契约。取 RISC-V 最小子集（6 条指令，够写真实程序）：

| 指令 | 语义 | opcode（[6:0]） | 其他字段 |
|---|---|---|---|
| `add rd, rs1, rs2` | rd = rs1+rs2 | **0110011** | funсt3=000, rd[11:7], rs1[19:15], rs2[24:20] |
| `addi rd, rs1, imm` | rd = rs1+imm | **0010011** | funct3=000, imm[31:20]（12 位立即数） |
| `lw rd, imm(rs1)` | rd = 内存[rs1+imm] | **0000011** | funct3=010 |
| `sw rs2, imm(rs1)` | 内存[rs1+imm] = rs2 | **0100011** | funct3=010（imm 拆两半编码） |
| `beq rs1, rs2, imm` | rs1==rs2 则跳转 | **1100011** | funct3=000（imm 编码偏移） |
| `jal rd, imm` | 跳转并存返回地址 | **1101111** | rd=返回地址 |

读表的三个要点：

1. **opcode 定格式**：R 型（寄存器三操作数）/ I 型（带立即数）/ S 型（store）/ B 型（分支）——字段位置**尽量对齐**（rs1 永远在 [19:15]）——**译码器只需要看 opcode+funct3 就知道其余字段怎么切**，这是 RISC 设计美学的核心（对齐字段=更少的 MUX）
2. **32 个寄存器**（rd/rs 5 位编码，mini 03 说过为什么是 32：多端口 SRAM 的面积平方律）
3. **6 条指令已图灵完备**（有条件跳转 + 有内存读写 + 有算术——理论上能写任何程序；实际上补 sub/移位等十几条就能跑 OS）

## 3. 数据通路：把零件摆上桌

```
            ┌────────────────────────────────────────────────┐
            │                                                │
[PC 触发器] ─→ 指令内存 ──→ [译码器+寄存器堆] ──→ [ALU] ──→ [数据内存] ─→ [写回 MUX] ─┐
   ↑32          取指        译码/读双寄存器      执行       访存(load/store)     写回      │
   │                                                                          │
   └─────────── PC+4（默认下一拍）←──── 加法器 ←────────────────────────────────┘
                分支时 PC ← PC+imm（ALU 判 beq 或专用比较器）
```

各站职责与零件出处：

| 站 | 干什么 | 零件 |
|---|---|---|
| PC | 当前指令地址（32 位 DFF） | 04 篇触发器 |
| 取指 | 指令内存[PC] → 指令字节 | mini 00 的 Flash |
| 译码 | opcode/funct3 查出控制信号；字段切出 rs1/rs2/rd/imm | 02 篇门网络 + **译码器** |
| 寄存器堆 | 32×32bit DFF 阵列，2 读口 1 写口 | 04 篇 + 译码器选行（5→32） |
| ALU | add/sub/and/or/slt…按 ALUOp 选 | 03 篇加法器 + **MUX** |
| 数据内存 | lw/sw 的读/写 | 内存（memory_work 01） |
| 写回 MUX | 写进 rd 的数据三选一：ALU 结果/内存读出/PC+4 | **MUX** |

## 4. 控制信号全表：译码器的输出就是它

译码器每拍从 opcode/funct3 算出 6 根控制线——**这张表就是"CPU 的灵魂"，也是硬连线控制器的全部**：

| 信号 | addi | lw | sw | beq | jal |
|---|---|---|---|---|---|
| RegWrite（写寄存器堆） | 1 | 1 | 0 | 0 | 1 |
| ALUSrc（第二操作数：寄存器/立即数） | 1(imm) | 1(imm) | 1(imm) | 0(rs2) | × |
| MemRead | 0 | 1 | 0 | 0 | 0 |
| MemWrite | 0 | 0 | 1 | 0 | 0 |
| MemToReg（写回源：ALU/内存） | 0(ALU) | 1(mem) | × | × | 0(PC+4) |
| Branch/PCSrc | 0 | 0 | 0 | **1** | (jal=1) |

`addi t0, t0, 4` 一拍的完整走查：

1. 取指：指令内存[PC] 出字节 `0042 82 93`（小端拆字段）
2. 译码：opcode=0010011 → 表第 2 列点亮：RegWrite=1, ALUSrc=1, ALUOp=ADD；rs1=7, rd=7, imm=4
3. 读数：寄存器堆译码器选 x7 → 读出旧值；立即数扩展器把 4 符号扩展成 32 位
4. 执行：ALU 加法（ALUSrc=1 选了 imm）
5. 写回：RegWrite=1 → 写回 MUX 选 ALU 结果 → x7 ← x7+4
6. PC ← PC+4

**六拍流水在单周期 CPU 里是一拍（长组合路径），在真实 CPU 里是六级（06 篇）**——先看懂逻辑，再看时序。

## 5. 进化点 I：三态门与总线——零件间的公路

§3 图里每站直连——32 位×多站 = 布线灾难。真实机器用**总线**（02 篇三态门的舞台）：

```
寄存器堆读口 ──┐
ALU 输出    ───┤ 三态门阵列 ──→ 内部总线 ──→ 各站输入
内存读出    ───┘   （任一时刻只允许一个源驱动总线）
```

- 任一时刻一个驱动源 + 全员 Z 态 + 译码器使能——02 篇的三态门直接上岗
- **现代片上实际换成了 MUX 网络**（每个目的端一个 MUX 选源，mini 01 的"电气共享→逻辑选择"）——三态总线在片内高频不可靠，但**概念原样保留**："总线的本质 = 任一时刻只有一个发言者"
- 主系列 01 篇的 4 条通道（内存/设备/中断/DMA）在电路层就是这张总线图的外延——**mini_machine 01 是本节的全面放大**

## 6. 进化点 II：微程序 vs 硬连线——控制器的两条路线

§4 那张控制表怎么实现？两条路线打了五十年：

- **硬连线**：控制信号 = 译码器输出的组合逻辑（与/或门网络）——快（一拍出信号），但指令集一改全重画（CISC 的复杂指令要海量状态位，电路噩梦）
- **微程序**（Wilkes 1951 提出，1964 IBM System/360 工业化）：把每条指令拆成**微指令序列**存在控制存储器（ROM）里，控制器变成"**微 CPU**"——取微指令 → 发控制信号 → 取下一条微指令。**指令的执行被解释成微程序的执行**

| | 硬连线 | 微程序 |
|---|---|---|
| 速度 | 快（纯组合） | 慢（每控制步一拍） |
| 改指令集 | 重画电路 | **改 ROM 内容**（固件升级！） |
| 代表 | RISC（RISC-V/ARM） | CISC（x86 至今：复杂指令在 µcode ROM 里展开成内部微操作） |

**历史裁决**：RISC 运动 selects 硬连线 + 简单指令（编译器负责复杂度）；x86 前端把 CISC 指令**翻译成类 RISC 的 µops**（06 篇）——**两条路线的合流：外部 CISC 兼容、内部 RISC 灵魂**。05 篇只需要记住：**控制信号表 = CPU 的灵魂，硬连线是查表，微程序是读脚本**。

## 7. 进化点 III：三个被按下的进化点

真实 CPU 史上，本篇电路刚合体时就面临的三个岔路——每个的"按下"都改写了后续：

### 7.1 中断 = PCSrc MUX 的第三个输入

§3 的 PC 更新只有两个来源（PC+4 / 分支目标）。外设要"叫人"（主系列 01 篇通道 3）→ **PC 需要第三个来源：中断向量地址**。

```
PC 来源 MUX： [PC+4] [branch 目标] [中断向量] ← 中断控制器握手成功时选第三个
```

电路上的就位成本几乎为零（MUX 加一个输入口 + 一根使能线）——**但软件世界的分页就此改写**：mini_machine 04 的 NVIC、主系列 02 的 IDT、一切驱动模型，全部从这个第三输入口长出来。

### 7.2 冯·诺依曼瓶颈 = 那条单总线

§3 图里指令和数据**同一条内存路**——取指与取数排队（00 篇哈佛 vs 冯诺依曼的裁决后果）。缓解史：L1 I/D 分家（哈佛回魂）→ 缓存层级 → 06 篇内存墙的全部话题。**05 篇按下的这个"单总线"决定，是 06 篇一切表演的舞台约束**。

### 7.3 栈 = RSP 寄存器 + 约定（硬件成本为零）

`call` 要保存返回地址、函数要用局部变量——解法：**留一个寄存器 RSP 当游标，约定 push = RSP-8 后写内存、pop 反向**（主系列 01 篇 §1 的约定）。硬件上 RSP 只是一个普通 32 位寄存器——**没有任何专门电路**。mini_machine 04 的"硬件自动压栈 8 寄存器"是它的豪华版（中断快照专用）。

**洞见：栈是最便宜的"万能分解器"——递归、函数调用、中断现场、表达式求值，全部用一个游标 + 两条约定解决。**

## 8. 本篇结论

1. 译码器（分发）与 MUX（收拢）补齐最后两块积木——**数字电路的左右手**。
2. **指令集先于电路**：opcode 定格式、字段对齐省译码、6 条指令图灵完备——契约思维是 CPU 设计的第一性。
3. 数据通路五站（PC/取指/译码执行/访存/写回）+ 控制信号 6 根线——**控制表就是 CPU 灵魂**；单周期走查 `addi` 六步可逐拍验证。
4. 三态总线让零件共享公路（后被 MUX 网络接棒）；**微程序 vs 硬连线五十年之争以"x86 外 CISC 内 RISC"合流收场**。
5. 三个进化点（中断第三输入口、单总线瓶颈、零成本栈）在电路图上各是一笔，在软件史上各是一个纪元。
