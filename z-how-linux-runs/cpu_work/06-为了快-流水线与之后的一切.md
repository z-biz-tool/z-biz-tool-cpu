# cpu_work 06 · 为了快：流水线与之后的一切（彻底版）

> CPU 合体了（05 篇），但它太慢——T_clk 被最坏组合路径钉死（04 篇宪法）。本篇彻底版：流水线把 T_comb 切成五段的完整推导，三类冒险与三种解法逐一对仗，缓存层级、µops/乱序、MESI 多核、功耗墙与 GPU 分岔——"为了快"的一切都是 04 篇不等式和 05 篇电路的下游。

## 1. 流水线：用沿切分 T_comb

04 篇宪法：`T_clk ≥ T_cq + T_comb + T_setup`。05 篇单周期 CPU 的 T_comb = 取指+译码+读寄存器+ALU+访存+写回的**总和**（比如 3ns → 最高 333MHz）。

**流水线的暴力与优雅**：在五站之间**插入触发器**，把长路径切成五段：

```
          IF     ID     EX    MEM     WB
          ┌──│───┬──│───┬──│───┬──│───┐
指令 N：   取指   译码   执行   访存   写回
指令 N+1：     取指   译码   执行   访存  …   ← N 在 EX 时 N+1 已在 ID
```

- 每段 T_comb ≈ 0.6ns → T_clk ≈ 0.6ns → **主频 1.6GHz**——×5
- 吞吐率 = 每 0.6ns 完成一条（理想）——**注意：单条指令延迟没变（仍 3ns，甚至更长，多了站间寄存器开销），变的是吞吐率**。"流水线加快 CPU"严格说是"加快流水率"
- 洗衣店类比落地：4 台洗衣机+4 台烘干机同时服务 4 批衣物 vs 一批一批串行——**前提是衣服可分批**（指令独立性——下面的"冒险"就是分批失败的时刻）

**段间寄存器（流水寄存器）**：04 篇的 DFF 阵列，每拍把本段结果锁给下段——**流水线的全部物理成本就是几排触发器 + 控制逻辑**，性价比史上最高。

## 2. 冒险：三只拦路虎（每只一个解法）

### 2.1 数据冒险：下一条要用上一条的结果

```
add x1, x2, x3     ← x1 在第 5 段(WB)才写回
sub x4, x1, x5     ← 但它在第 2 段(ID)就要读 x1 —— 早了 3 拍！
```

朴素解法：**流水线停顿（stall/bubble）**——sub 在 ID 等 3 拍，吐 3 个气泡（吞吐 ×0.6）。每条相关都停 3 拍？流水线白搭。

**正解：旁路/前递（bypass/forwarding）**——x1 的结果在第 3 段(EX)结束时**已经存在于 ALU 输出端**！何必等写回？加一组 MUX 把"上一条指令的 ALU 输出"直接喂给本条 ALU 的输入：

```
EX/MEM 段寄存器 ──┐
                  [MUX] → ALU 输入 A    （forwarding MUX：从旧值/旁路值里选）
寄存器堆读出  ────┘
```

- load-use 例外：lw 的数据第 4 段(MEM)末才有 → 下一条若用它**必须停 1 拍**（硬件自动检测 + 1 拍气泡）——**load-use hazard 是唯一绕不开的数据停顿**
- 旁路网络 = 一堆 MUX + 一套"相关检测比较器"（比较相邻指令的 rd/rs 字段）——**空间换时间母题又一次登场**

### 2.2 控制冒险：分支要到 EX 才知道跳不跳

```
beq x1, x2, target   ← 第 3 段才知道结果
（PC 已按"不跳"预取了 2 条后续指令 —— 跳了就要作废/冲刷 flush）
```

演进史（每一代都在赌得更深）：

1. **冻结**：分支后排空流水线——吞吐 ×0.6，太亏
2. **静态预测**：向后跳（循环）预测跳、向前预测不跳——猜对率 ~70-80%
3. **动态预测（1 位/2 位饱和计数器）**：一张表按 PC 索引，记每分支的历史——1 位：上次跳这次也跳（循环边界各错 1 次）；**2 位饱和**（强跳-弱跳-弱不跳-强不跳）：循环内部零误判，只边界 1 次——95%+
4. **现代**：TAGE/感知机/历史模式匹配， speculation depth 15+ 级，猜对率 99%——**分支预测错 = 冲刷整条流水线（20 拍白干），预测器成为 CPU 最贵资产之一**
- （Spectre 漏洞（2018）：预测执行会访问被预测的错误路径、留下缓存痕迹——**预测的代价**：错误路径的副作用可以被侧信道观察。性能优化的安全性税。）

### 2.3 结构冒险：两件东西抢一个零件

例：指令与数据共用一个内存口（05 篇冯诺依曼瓶颈的流水线版）——IF 与 MEM 撞车。解法：**哈佛化（L1 分成 I-cache/D-cache，00 篇"表哈佛"裁决的落地）**。

## 3. 缓存层级：内存墙下的必答题

流水线喂饱的前提是取指/取数跟得上——但 memory_work 01 §8 的账：DRAM 100ns = **500 拍 @5GHz**。每拍访存都等 500 拍？流水线当场死亡。

**答案 = 缓存层级**（SRAM 小而快，赌局部性）：

```
L1 I/D（各 32KB，4 拍）→ L2（512KB-2MB，12 拍）→ L3（几-几十 MB，40 拍）→ DRAM（200-500 拍）
```

- 工作方式：按 **64B 缓存行**搬运（空间局部性的兑现——用一个字节，白拿 63 个邻居）
- 命中率 95%+ 时平均访存 ~几拍——**赌局（memory_work 05 §2）在硬件的最后一次下注**
- 组织：组相联（内存地址 → 组号 → 组内 N 路比较 tag）——全相联太贵、直接映射冲突率高，组相联是折中（又是空间换时间/硬件复杂度的取舍）

## 4. µops 与乱序执行：CISC 外壳、RISC 灵魂

x86 指令（CISC，1-15 字节、复杂寻址）与 5 级流水线（RISC 假设）的和解——**前端翻译**：

```
mov rax, [rbx+rcx*8+16]   ← 复杂 CISC
   ↓ 前端译码
µop1: load tmp ← [rbx+rcx*8+16]     （简单微操作）
µop2: add  rax, tmp
```

- µops（micro-operations）= 05 篇 RISC 式简单操作的内核版本；多数 x86 指令 1-4 µops，超长指令（string ops）走**微码 ROM**（05 篇微程序的当代归宿）
- **乱序执行（OoO）**：µop 流水线遇到依赖/缓存缺失会停——**等着也是等着，不如先执行后面无关的指令**：
  - **重命名**：x86 只有 16 个架构寄存器（mini 03 说的历史包袱），但物理寄存器有 300+——把架构寄存器动态映射到物理寄存器，**消除"假依赖"**（连续两次写 rax 根本不用排队）
  - **保留站/调度器**：每拍从几十个就绪 µop 里挑最多的发
  - **顺序提交（ROB）**：执行可以乱，**结果按程序序落账**——异常/中断的语义才能保持
- 效果：IPC（每拍指令数）从 1 → 4-6；代价：**功耗与面积指数上涨**——这是高端 CPU 每代变贵的根源

## 5. 多核与 MESI：一致性税

频率撞墙后（§7），性能靠核数。两核各有 L1/L2，同一地址两份副本——**缓存一致性**必须硬件保证（软件同步解决不了"缓存里已有旧值"）：

**MESI 四态协议**（每缓存行一个状态）：

| 状态 | 含义 | 本核读 | 本核写 |
|---|---|---|---|
| M Modified | 最新且唯一 | 命中 | 直接 |
| E Exclusive | 最新且唯一但干净 | 命中 | 静默升级 M（不发总线消息！） |
| S Shared | 干净，可能有副本 | 命中 | **广播失效（Invalidate）→ 等其他核确认 → 升 M** |
| I Invalid | 无效 | **总线取**（从内存或别的核） | 同上 |

- **代价实例**：核 A 写、核 B 也写同一行（false sharing：两个变量恰好同行）→ 总线上 Invalidate 消息乒乓，**每拍往返 100+ 拍**——并行程序慢成串行的经典陷阱（主系列 P2/P4 的硬件底牌）
- 内存屏障/内存序（x86 TSO 宽松度低、ARM 弱序）——**乱序执行的世界里"程序序"要靠屏障手动恢复**（mini 04 DMA 一致性的大机器版）

## 6. 进化点 I：功耗墙——CV²f 与 2005 年的大刹车

01 篇埋的公式在此收账：`P_dyn = C·V²·f`（每拍翻转电容负载）。1990-2005 的美好循环：

```
工艺缩小 → C 变小 → 可以同时升 f 和降 V → P 大致不变（Dennard Scaling：单位面积功耗恒定）
```

**~2005 年失效**：漏电流（亚阈值漏电）随 V 降低占比暴涨 + V 降不动了（Vth 有底）→ **P 密度失控**。 Pentium 4 的 4GHz 梦（Tejas 胎死腹中）就此终结——

**行业集体转向：不再升频率，改堆核**（多核时代 ~2005 至今）+ 门控时钟/DVFS（mini 02）/big.LITTLE 异构。**主频停滞 20 年不是技术失败，是物理判决**——04 篇 T_clk、05 篇电路、本篇流水线的全部优化，最终都要向 CV²f 低头。

## 7. 进化点 II：Amdahl 定律——并行的天花板

堆核的收益由可并行比例决定：

```
加速比 = 1 / (S + (1-S)/N)      S = 必须串行的比例
S=10%：∞ 个核也只有 10×
S=1%： 64 核实际 39×，1024 核 91×——边际急剧递减
```

**推论**：并行编程的圣杯不是"会用多核"，是**消灭串行比例**（锁、全局状态、I/O 等待）——主系列后续章节（同步原语、无锁结构）的全部战争在此立项。**Amdahl 与 MESI/false sharing 是同一枚硬币：并行度被通信成本钉死。**

## 8. 进化点 III：GPU 分岔——另一种"快"

CPU 把复杂度花在"单线程快"（乱序/预测/大缓存——面积 90% 在管理）；**GPU 反向**：

```
CPU 核心：复杂、少（几十）、缓存巨大、面向延迟
GPU 核心：极简（无乱序、无大缓存）、海量（上万）、SIMT（一群核心执行同一条指令、各带各的数据）
```

- 图形/矩阵乘的天然属性：**海量数据 × 同构运算 × 强空间局部性**——SIMT 赌局比 CPU 的乱序赌局简单粗暴得多
- 延迟 vs 吞吐：CPU 藏延迟（缓存+预测），GPU 用线程切换淹没延迟（ warp 切换 0 拍）——**两种赌注对应两种负载**；AI 时代 GPU 胜出的本质：神经网络的算子形态完美契合 SIMT
- SoC 终局：CPU+GPU+NPU+ISP 同片（mini 00 的 MCU 思想长成大机器）——**"专用加速器"是通用 CPU 在功耗墙+内存墙下的出路，不是否定**

## 9. 本篇结论

1. **流水线 = 用触发器切 T_comb**：吞吐 ×段数（延迟不变），全部成本几排 DFF——04 篇不等式的第一次兑现。
2. 三只冒险对仗三只解法：数据→旁路 MUX（load-use 除外）、控制→预测器（1 位→2 位→TAGE，99% 赌局）、结构→哈佛化 L1。
3. 缓存层级赌局部性赚回 100× 时间差；**组相联=成本与命中率的折中**；MESI 用总线消息买一致性，false sharing 是并行程序的头号暗坑。
4. µops 让 x86 完成外 CISC 内 RISC 的合流；乱序三件套（重命名/调度/顺序提交）把 IPC 推到 6——**复杂度与功耗同涨**。
5. **功耗墙（2005）是 CV²f 的物理判决**：频率让位核数；Amdahl 给核数封顶；GPU/SIMT 用"简单+海量"在另一象限突围——三个进化点共同宣布：**"为了快"进入了与物理谈判的时代**。
6. 回到主系列：CPU 已到极限速度，OS 的任务（03 篇起）是把这颗"5GHz、乱序、多核、带大缓存"的机器**伪装成许多个顺序执行的小世界**——硬件的白热化正是 OS 复杂度的起点。
