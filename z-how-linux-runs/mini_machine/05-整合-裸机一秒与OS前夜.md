# mini_machine 05 · 整合：裸机一秒与 OS 前夜

> 前 4 篇把每个板块拆开看过。本篇合体：**按下电源后的完整一秒**、一段 60 行的完整裸机程序、一次按键的全链路走查——
> 最后，盯着这个程序看它长大，**你会亲眼看到 OS 的形状从裸机里自然长出来**。这是通往主系列 02 篇的最后一块跳板。

## 1. 通电一秒：全流程总装图

```
按下电源
  ↓ 电源爬升（去耦电容蓄水，00 篇）
POR 拉住复位，全机冻结（02 篇）
  ↓ VDD 过 BOD 阈值
晶振起振（ms 级）→ PLL 锁定 → 168MHz 心跳（02 篇）
  ↓ 时钟稳
复位释放 → CPU 读 0x0000_0000/0004 → SP、PC 就位（02 篇）
  ↓
Reset_Handler：搬 .data、清 .bss（02 篇）
  ↓
main()：开时钟门控 → 配 GPIO/UART/Timer → 订阅中断（03/04 篇）
  ↓
主循环 + 中断在背后随时插入 —— 机器彻底活了
```

**每一格都指向前面某篇的电路**——这就是"整合"的含义：没有新零件，只有接线。

## 2. 一台完整的裸机程序（60 行，寄存器级，可烧录）

功能：SysTick 每 500ms 闪灯 + UART 中断收字节 echo 回去 + DMA 收命令帧。

```c
#include <stdint.h>
/* ---- 寄存器别名（00 篇 MMIO + 03 篇面板）---- */
#define RCC_AHB1ENR  (*(volatile uint32_t*)0x40023830)
#define GPIOA_MODER  (*(volatile uint32_t*)0x40020000)
#define GPIOA_ODR    (*(volatile uint32_t*)0x40020014)
#define STK_LOAD     (*(volatile uint32_t*)0xE000E014)
#define STK_CTRL     (*(volatile uint32_t*)0xE000E010)

volatile uint32_t ticks;                    /* 04 篇：volatile！ */
volatile char     rx_buf[64];
volatile uint32_t rx_len;

/* ---- 中断服务：硬件自动跳入（04 篇）---- */
void SysTick_Handler(void)  { ticks++; }                          /* 系统心跳 */
void USART2_IRQHandler(void) {
    rx_buf[rx_len++ & 63] = *(volatile char*)0x40004404;          /* 读 DR 顺带清 RXNE */
}

/* ---- main：全部初始化就是"写面板"（03 篇）---- */
int main(void) {
    RCC_AHB1ENR |= (1 << 0);            /* ① GPIOA 时钟门控（02 篇：先供电再说话） */
    GPIOA_MODER |= (1 << 10);           /* ② PA5 输出模式（LED） */
    STK_LOAD = 84000 - 1;               /* ③ SysTick：84MHz/84000 → 1ms */
    STK_CTRL = 7;                       /* ④ 使能 + 选 CPU 时钟 + 订阅中断 */
    /* ⑤ UART2/中断/DMA 配置略（03/04 篇模板），全部是同一套：写 CR、开 NVIC */
    for (;;) {                          /* ⑥ 裸机主循环 */
        uint32_t now = ticks;
        if (now % 500 == 0) GPIOA_ODR ^= (1 << 5);   /* 500ms 闪灯：数心跳 */
        if (rx_len >= 4) {                            /* 收满 4 字节命令帧 */
            for (volatile int i = 0; i < rx_len; i++)
                *(volatile char*)0x40004404 = rx_buf[i];  /* echo 回去 */
            rx_len = 0;
        }
    }
}
```

- **初始化的全部动作都是"写寄存器"**——没有魔法，00 篇的 MMIO 地图 + 03 篇的面板 + 04 篇的订阅
- 主循环既不阻塞等串口也不阻塞等时间：**闪灯数中断计数、收包由 ISR 攒**——03 篇的轮询烧 CPU 问题已经消失
- 这就是一台真正的机器：**CPU、SRAM、Flash、总线、时钟、复位、外设、中断、DMA 全员在岗**

## 3. 一次按键的全链路走查（跨系列对账的总验收）

用户按下接在 PA0 的按键：

| 步骤 | 发生什么 | 出处 |
|---|---|---|
| 1 | 触点抖动的模拟电平 → 施密特触发器整形 | mini 03 |
| 2 | EXTI 检测上升沿 → 事件线拉高 | mini 04 |
| 3 | NVIC 置 pending、仲裁、发"叫人"信号 | mini 04 |
| 4 | CPU 硬件压栈 8 寄存器、查向量表、跳 handler | mini 04（cpu_work 05 的栈=MUX 约定升级成硬件规约） |
| 5 | handler 置标志，主循环读到后 UART 发日志 | mini 03/04 |
| 6 | 写 TDR → 移位寄存器按 115200 撕字节 → TX 电平 | mini 03 |
| 7 | 日志到达对端 PC，期间 CPU 大部分时间在睡觉/干别的 | mini 04 |

**七个环节、零个 OS**——纯硬件 + 60 行裸机代码完成了"输入→处理→输出"的完整闭环。

## 4. OS 前夜：裸机程序长大后必然长出的形状

给这台机器继续加需求，看裸机程序员会被迫发明什么：

| 新需求 | 裸机的土办法 | 它其实是 |
|---|---|---|
| "顺便再闪第二个灯" | SysTick 里再加一行计数 | **调度：谁在什么时候跑** |
| "串口收发同时进行" | 两个方向各一份缓冲 + 标志 | **生产者-消费者缓冲（P1）** |
| "处理不能被打断的配置" | `__disable_irq()/enable()` 圈起来 | **临界区/锁（P2、P4）** |
| "延时 100ms 再做事" | 数 SysTick 心跳 | **时钟驱动的睡眠/唤醒（P7）** |
| "LED 模块和 UART 模块都要用 PA9" | 手写"占用表"逐个登记 | **资源管理/独占访问（P5）** |
| "某个功能死了要能自愈" | 看门狗 + 心跳标志（02 篇硬件原型） | **健康检查/看护进程** |
| "DMA 和 CPU 共享一块缓冲" | 约定"谁在用谁不许碰" | **内存一致性（P3 前奏）** |

**右列的每一个名字，都是主系列 02 篇的 P1~P7 问题在裸机上的最小版本**（02 篇的核心论断："所有答案都是同一个形状"——这个形状在裸机上就已经显现）。

- 当缓冲、锁、调度表、睡眠唤醒全部要"通用化、给每个模块复用"时——**它们不再是某个程序里的技巧，而是一层独立的公共软件**。
- 这层软件的名字就叫 **OS**。主系列 02 篇的全部逻辑（问题暴露 → OS 介入）在 mini 机器上都有 1:1 的最小预演。

**统一洞见：OS 不是从天上掉下来管机器的——OS 是裸机程序在需求压力下长出的公共骨架。** mini_machine 系列到此合体：cpu_work 的算 + memory_work 的记 + 本系列的连 = 主系列 01 篇的"那台规约机器"；它身上的每一种手忙脚乱 = 主系列 02 篇的开场问题清单。

## 6. 本篇结论

1. 通电一秒 = 七件套按序苏醒：电源 → 复位 → 时钟 → 向量 → startup → main → 主循环。
2. 60 行裸机程序驱动整机：初始化即写面板，主循环 + ISR 即全部软件。
3. 一次按键走查七环节零 OS——闭环在硬件上完整成立。
4. **裸机程序长大必长出 OS**：缓冲/锁/调度/睡眠唤醒/资源管理在需求压力下逐一显形，它们就是主系列 02 篇 P1~P7 的最小版。
5. 整机零件 100% 可回溯到 cpu_work + memory_work + 本系列——黑盒拆解到此闭合。
