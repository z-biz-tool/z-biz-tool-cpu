# mini_machine 00 · 蓝图：最小计算机系统

> 零件都有了：CPU（cpu_work 05）、SRAM/Flash（memory_work 01/02）。现在造机器。
> 本篇先回答"最少要几个零件"，并给出全系列要用的那张**地址地图**——后面每一篇都在这张地图上活动。

## 1. 一台机器的最小构成：七件套

| # | 零件 | 出处 | 干什么 |
|---|---|---|---|
| 1 | CPU 核 | cpu_work 05 | 取指-执行 |
| 2 | SRAM | memory_work 01 | 存变量、栈 |
| 3 | Flash | memory_work 02 | 存程序（断电不丢） |
| 4 | 总线 | 本系列 01 | 让三者互相对话 |
| 5 | 时钟 | 本系列 02 | 心跳 |
| 6 | 复位 | 本系列 02 | 苏醒起点 |
| 7 | 电源 + 去耦 | 本篇 §4 | 供血 |

外设（GPIO/UART/Timer）、中断控制器、DMA 是随后挂上来的肌肉与神经（03/04 篇）。

## 2. MCU 是什么：把整台机器缩进一颗芯片

1971 年 Intel 4004：CPU 一颗、RAM 一颗、ROM 一颗，焊在一块板上。今天：

- **MCU（单片机）** = CPU 核 + SRAM + Flash + 全部外设 + 总线，**一颗芯片**。Arduino Uno 里的 ATmega328P（AVR 核，2KB SRAM，32KB Flash）、STM32（Cortex-M 核，几百 KB SRAM/1MB Flash）都是。
- **MPU（应用处理器）** = 只集成 CPU + 大缓存，SRAM/DRAM/存储在外挂——你的手机 SoC、PC CPU 是这一类。

**差别不是大小，是"信任边界"**：MCU 的所有东西都在同一块硅上、同一张总线上、一个地址空间里——没有任何东西需要"协议协商"，连上就能用。这正是学习"硬件怎么协作"的最佳标本：**所有协作都看得见**。

## 3. 地址地图：一切归一（MMIO）

cpu_work 05 的 CPU 只会"取指/读写内存"。要让"读写外设寄存器"也成为一次普通的访存——**给外设分配地址**。这就是内存映射 IO（MMIO）：

```
0xFFFF_FFFF ┌───────────────┐
            │  系统私有区     │  NVIC、SysTick、调试口（04 篇）
0xE000_0000 ├───────────────┤
            │   外设区       │  GPIO 0x4002_0000
0x4000_0000 │  （寄存器）    │  UART 0x4000_4400
            │               │  Timer 0x4000_0000 …
0x2000_0000 ├───────────────┤
            │   SRAM        │  变量、栈（memory_work 01）
0x0800_0000 ├───────────────┤
            │   Flash       │  程序 + 向量表（memory_work 02）
0x0000_0000 └───────────────┘  ← 复位后从这里启动
```

从此 CPU 眼里只有内存：**写 0x4002_0014 不是"控制外设"，就是一次普通的 store**——落下去的那一拍，GPIO 引脚真的会变电平。主系列 01 篇「通道 2：读写设备寄存器」的电路本质就在这：**外设把自己伪装成内存**。

- 对比 x86 的老路：独立端口空间 + 专用 in/out 指令（第二套地址）。现代 ARM 全走 MMIO——一套地址、一套指令、一个页表管到底。
- 大小端：Cortex-M 默认小端（低位字节在低地址）——int 0x11223344 存 44 33 22 11。

## 4. 电源与去耦：最容易被忽略的第七件

CPU 每拍翻转几百万个门，电流瞬间抖动几百 mA。走线有电感，电流突变时电压塌陷（V = L·di/dt）——**没有本地蓄水池，电源轨会晃出毛刺，CPU 跑飞**。

- 每个电源引脚旁 100nF 陶瓷电容（高频蓄水池）+ 每区域 10μF（低频水库）——这就是"去耦电容"：**把电源的高频阻抗降到近乎零**
- 复位电路外面还挂一颗 RC（上电时复位引脚慢释放，02 篇细讲）

## 5. 哈佛 vs 冯诺依曼：蓝图上的最终选择

| 架构 | 指令与数据 | 谁在用 | 后果 |
|---|---|---|---|
| 冯诺依曼 | 同一存储、同一总线 | Cortex-M0、x86 | 一条总线，简单；取指与取数排队 |
| 哈佛 | 分开的存储与总线 | AVR、Cortex-M3/M4（I/D Code 双总线） | 同时取指+取数，快；但"程序存储"和"数据存储"要两套访问路径 |

Cortex-M3 折中：SRAM/Flash 都在同一地址空间（软件看起来冯诺依曼），但**总线内部分指令口和数据口**——名字叫哈佛总线、地图长得像冯诺依曼。**机器设计的常态：架构之争以折中收场**（cpu_work 00 前传的哈佛/冯诺依曼之争在这里落地）。

## 6. 本篇结论

1. 最小系统 = CPU + SRAM + Flash + 总线 + 时钟 + 复位 + 电源去耦——七件缺一不转。
2. MCU = 整个最小系统缩进一颗芯片；MCU 是学"硬件协作"的最佳标本，因为所有协作都发生在同一块硅上、看得见。
3. **MMIO 是全系列的支点**：外设伪装成内存，CPU 一条 store 指令就能驱动世界；主系列 01 的"通道 2"由此而来。
4. 去耦电容不是可选项：电流突变 × 走线电感 = 电源塌陷 = 跑飞。
5. 哈佛/冯诺依曼之争以"同地址空间 + 分总线口"的折中落地。
