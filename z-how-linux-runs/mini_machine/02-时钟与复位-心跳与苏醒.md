# mini_machine 02 · 时钟与复位：心跳与苏醒

> 总线把零件连上了（01 篇），但所有触发器都在等同一件事：**时钟沿**（cpu_work 04）。
> 本篇讲心跳从哪来、怎么分给全身，以及机器怎么从"一片混沌"精确地醒来。

## 1. 时钟源：石英为什么准

| 源 | 原理 | 精度 | 启动 | 用途 |
|---|---|---|---|---|
| 内部 RC 振荡器（HSI） | RC 充放电翻转入振荡 | ±1% | 微秒级 | 快速启动、低成本场景 |
| **石英晶振（HSE）** | 压电效应：机械谐振 | ±10~50 ppm | **ms 级起振** | UART 高波特率、USB 等计时敏感场景 |

石英晶片的机械谐振 **Q 值 10⁴~10⁶**（普通 LC 回路 ~100）——谐振曲线极尖锐，只在一个频率上稳定振荡，频率漂移以 ppm（百万分之一）计。**UART 收发双方各拿各的时钟（01 篇没有共享时钟线！），115200 波特率下误差必须 <2%**——内部 RC 勉强，晶振稳妥。（外设间没有共享时钟是"异步串行"的本义：双方约好波特率，各自数拍。）

## 2. PLL：心跳倍频器

晶振受物理限制做不高（MHz 级），CPU 要 100+MHz——**锁相环（PLL）**：

```
8MHz 晶振 → [相位比较器] → [电荷泵] → [VCO 压控振荡器] ─┬→ 168MHz 输出
              ↑                          ↑               │
              └──── [÷N 反馈分频器] ←──────┴─────── 168/N
```

- 相位比较器发现输入与反馈的相位差 → 调 VCO 电压 → 直到 8MHz × N = 输出
- 8MHz × 21 = 168MHz：**输出频率锁死为输入的整数倍，抖动与晶振同级**
- 锁定需要时间（μs~ms）——**上电序列必须等 PLL lock**，02 §6 详说

## 3. 时钟树：一根心跳分发到全身

```
HSE 8MHz ──┐
           ├→ PLL → 168MHz → AHB/HCLK(168) → CPU核
HSI 16MHz ─┘                    │           ├→ APB1 分频÷4 → PCLK1 42MHz → UART2/Timer2..
                                │           └→ APB2 分频÷2 → PCLK2 84MHz → UART1/ADC
                                └→ SysTick（04 篇的 OS 心跳候选）
```

- **分频**：外设不都跑 CPU 频率——UART 分频出 115200（03 篇）、APB 分频省电
- **门控时钟（clock gating）**：每个外设一个时钟闸门，不开就完全不走动、不走电——**这是 MCU 省电的第一大招**
- **每个 MCU 新手都踩过的坑**：往 UART 寄存器写数据毫无反应——因为**忘了先开这个外设的时钟门控**（RCC->APB1ENR |= USART2EN）。寄存器电路没有时钟 = 触发器全是死态，写不进读不出。**"先供电再说话"是硬件纪律第一条**。

## 4. 复位：不是拉低一根线那么简单

复位 = 把所有触发器强制回已知态。MCU 有五种复位来源：

| 来源 | 电路 | 为什么需要 |
|---|---|---|
| **POR 上电复位** | 电源监控器在 VDD 爬升期间拉住复位 | 电压不足时触发器乱态，乱跑会写坏 Flash |
| **BOD 欠压复位** | 电压跌破阈值（如 1.8V）强制复位 | 运行中电池跌落，宁可重启不可乱写 |
| NRST 外部引脚 | 按键/调试器拉低 | 手动重启、烧录器接管 |
| **看门狗 WDG** | 倒计数器归零即复位，软件须定期"喂狗" | 程序跑飞（中断被关/死循环）时**纯硬件兜底** |
| 软件复位 | 写系统控制寄存器 | 程序自己要求重启 |

**看门狗值得单独一句话**：它是机器里唯一一个"不信任软件"的零件——OS 的"心跳超时/系统自愈"思想的最小硬件原型（主系列 02 篇 P1 的极简版）。

## 5. 苏醒的第一拍：取向量

复位释放后（所有时钟已稳），CPU 做的头两件事**不是取指令**：

```
1. 从 0x0000_0000 读一个字 → 装进 SP（栈指针）
2. 从 0x0000_0004 读一个字 → 装进 PC（Reset_Handler 地址）
3. 然后才开始取指执行
```

- **为什么先要 SP？** 因为 Reset_Handler 是 C 代码，C 函数要用栈——**硬件必须先把"软件存在的地基"铺好**。Flash 最前面 8 个字节是整个软件世界的地基（主系列 01 篇 RIP=0xFFF0 的同构设计：**硬件从不"想"，它只按约定读固定地址**）。
- 这 8 个字节由链接脚本 + 启动文件安排，不是编译器自动的——**"main 是起点"是 C 程序员的幻觉，起点是向量表**。

## 6. main 之前：startup 的三件事

从 Reset_Handler 到 main() 之间，启动代码（startup.s / 启动 C）必须：

1. **搬 .data**：已初始化全局变量 `int x = 5;` 的初值 5 存在 **Flash** 里，但变量本体要活在 SRAM——启动代码把初值区 Flash→SRAM 复制一遍
2. **清 .bss**：未初始化全局变量按 C 标准必须为 0——**这个 0 不是白来的**，是启动代码把 .bss 段 SRAM 逐字清零
3. **调 main()**

加上 §5：**上电 → SP → PC → 搬 .data → 清 .bss → main**——"C 环境"是启动代码手工搭建的舞台。主系列 01 篇 0x7C00 的 BIOS 规约、Linux 内核的启动汇编，做的是同一类事。

## 7. 上电一秒的完整时序（与 05 篇呼应）

```
t0   VDD 爬升 → POR 拉住复位，全机冻结
t1   VDD 过 BOD 阈值，时钟源开始起振（晶振要 ms）
t2   复位释放条件齐：电源稳 ∧ 时钟稳
t3   CPU 取 SP、PC（Flash 前 8 字节）
t4   startup：搬 .data、清 .bss
t5   main()：开外设时钟门控 → 配置外设（03 篇）→ 开中断（04 篇）
t6   进入主循环/等待中断——机器活了
```

## 8. 本篇结论

1. 晶振准在 Q 值；RC 快但糙——**精度与启动速度的取舍**，UART 波特率是精度要求的现实来源。
2. PLL 用"相位锁死"把 MHz 晶振倍频成百 MHz 心跳；锁定需要等待。
3. 时钟树 = 分频 + 门控；**用外设先开门控时钟**是硬件纪律第一条。
4. 五种复位来源各有职责；POR/BOD 守住"电压不稳不乱跑"，看门狗守住"软件死了硬件救"。
5. 复位第一拍取向量表：先 SP 后 PC——**硬件先铺软件的地基，然后才轮到软件**。
6. .data 复制与 .bss 清零不是编译器魔法，是启动代码的手工劳动——C 环境是被搭建出来的。
