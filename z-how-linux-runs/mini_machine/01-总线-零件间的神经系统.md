# mini_machine 01 · 总线：零件间的神经系统

> 00 篇的地址地图是"规划"，本篇把路真的修出来。
> **总纲：总线 = 地址（去哪）+ 数据（运什么）+ 控制（怎么运）三组线的共享电路，配上"什么时候谁能说话"的纪律。**

## 1. 三组线

```
 CPU                总线               SRAM
┌──────┐      ┌──────────────┐      ┌──────┐
│      │─────→│ A[31:0] 地址 │─────→│      │
│      │ ←──→ │ D[31:0] 数据 │ ←──→ │      │
│      │─────→│ CTRL 控制     │─────→│      │
└──────┘      │ (读/写/使能)  │      └──────┘
              └──────────────┘
```

- **地址总线**：32 根，值决定"谁是这拍的主人"——译码器（cpu_work 05）按地址区间使能对应的模块。SRAM 译码 0x2000_0000~0x2000_FFFF，GPIO 译码 0x4002_xxxx——**每个地址段的译码器只在自己区间放行**。
- **数据总线**：32 根，双向（读/写共用；早期机器分单向两条，现代片上总线复用）。
- **控制总线**：读/写方向、字节使能（4 根，挑出 4 字节中要动哪几根）、传输完成信号。

三态门（cpu_work 02）在这里登场：同一拍只允许一个模块驱动数据总线，其余全部置 Z——**"共线"靠 Z 态实现**。

## 2. 速度不齐怎么办：两线握手（valid/ready）

CPU 60MHz，SRAM 一拍能接，Flash 要两个，UART 寄存器更慢。硬等？浪费。硬猜？出错。工业解法——**握手**：

```
 master（发起方）：VALID=1   →  "数据/地址有效，请收"
 slave（接收方）：READY=1    →  "我收下了，下一拍见"
```

- 传输在 VALID∧READY 同拍成立时完成——**谁慢谁拖 READY**，快慢自适配
- 这是所有片上总线（AHB/AXI/APB 变体）的共同骨架：**valid/ready 两根线，替代了"猜时序"**。I²C/SATA/USB 里看到的 ACK/NAK 全是它的后代。

## 3. 层级总线：AHB + APB（快慢分道）

一条总线伺候所有模块 → 最慢的 READY 拖死全员。真机的做法是**分级**（ARM 的 AMBA 标准，1996 年至今）：

```
CPU ─┐                                  SRAM ──┐
DMA ─┼── AHB 高速总线（流水线，一拍一传）─ Flash ──┤
                                        桥 ────┘
                                          │ 桥（慢速代理）
                              ┌───────────┴───────────┐
                              │  APB 慢速外设总线        │
                              │  GPIO/UART/Timer/ADC   │
                              └───────────────────────┘
```

- **AHB**：高速主干。流水线化——第 N 拍传数据的同时锁存第 N+1 拍的地址。
- **APB**：外设总线。极简（两条相位完成一次读或写）、便宜、慢；外设都不赶时间。
- **桥**：一个"翻译 + 缓冲"模块，master 端对 AHB 快速应答，slave 端慢慢转发到 APB。CPU 写 UART 寄存器 = AHB 一拍交付给桥，桥再花几拍转给 APB——**CPU 不等**。
- 外设时钟（PCLK）比 AHB（HCLK）慢（02 篇时钟树分频）——**快慢总线连时钟都分频**。

## 4. 等待周期：Flash 的现实课

不借助握手时最先撞墙的是 Flash：memory_work 02 说过 NAND/NOR 慢——MCU 内嵌 Flash 读出 ~25ns，60MHz CPU 一拍 16.7ns，**一拍根本读不出一条指令**。解法：

- **等待周期（wait state）**：Flash 在 AHB 上把 READY 拖 1-2 拍再交数据——兼容，但 CPU 插水
- **预取缓冲（prefetch）**：Flash 控制器赌"下一条指令大概率顺序"，趁 CPU 执行时提前读两行候着——命中率 >90%
- **缓存**：M7 干脆给 Flash 配 Cache

**进化点**：这解释了 STM32 主频表里的"0WS/1WS/2WS @ 频率"——**主频越高，Flash 相对越慢，等待越多**；也是 02 篇"PLL 倍频不能无脑拉满"的另一半原因。

## 5. 多 master 抢路：总线仲裁

CPU 不是唯一的发起者——DMA（04 篇）也要搬数据。两个 master 同时要总线：

- **仲裁器**：固定优先级或轮转（Round-Robin），把总线使用权判给一方，另一方等待——**每个 master 先申请（HBUSREQ）再使用，仲裁器发授予（HGRANT）**
- 策略考量：DMA 搬大块可拆 burst（一次连发 N 拍），仲裁在 burst 间隙插空——**CPU 感觉不到 DMA，因为 DMA 只在缝隙里偷拍**
- **进化点（三态总线 → MUX 互连）**：三态共线在片上高频不可靠（大电容、反射），现代片上总线用**多路选择器矩阵**替代：每个 slave 面前一个 MUX，由仲裁逻辑选当前 master——总线的"共享"从电气共享变成逻辑选择。再往上是 AXI（读/写通道分离、可乱序完成、多周期握手）与 NoC（多核 SoC 里总线变网络）——**总线没死，只是长成了交换机**。

## 6. 一次完整的跨总线写（走查）

CPU 执行 `USART2->DR = 'A'`（地址 0x4000_4400）：

1. CPU 发 AHB 传输：地址 0x4000_4400 + 写 + 数据 0x41 + VALID
2. 译码：落在 APB 桥的区间 → 桥以 READY 立即应答（AHB 侧一拍完成）
3. 桥暂存这笔写，转入 APB 节拍：setup 拍（置地址/写信号）→ access 拍（使能落笔）
4. UART 内部：APB 接口把 0x41 写进发送数据寄存器 TDR（03 篇接管）

**CPU 全程只感知了第 1-2 步的一拍**——后面全是桥与外设自己的事。

## 7. 本篇结论

1. 总线三件套：地址（译码使能选择主人）+ 数据（三态/MUX 共享）+ 控制（方向与握手）。
2. **valid/ready 握手是快慢世界的通用语**：谁慢谁拖 READY，无需猜时序。
3. AHB+APB 层级 = 快慢分道 + 桥缓冲；CPU 永远不等慢外设，等的是桥。
4. 等待周期与预取缓冲暴露 Flash 的物理慢——主频表里的 WS 不是玄学。
5. 仲裁让 DMA 与 CPU 共存：burst + 轮转让 DMA 藏在缝隙里。
6. 进化主线：三态总线 → MUX 互连 → AXI 通道分离 → NoC；**共享的电气形态一直在变，"谁先申请谁使用"的纪律不变**。
