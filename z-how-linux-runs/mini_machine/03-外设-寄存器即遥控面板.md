# mini_machine 03 · 外设：寄存器即遥控面板

> 机器活了（02 篇），但手无寸铁——CPU 连一根线都摸不到外面的世界。
> 本篇拆三个标准外设（GPIO/UART/Timer）的完整电路，并给出它们的**统一形态：自动状态机 + 一组寄存器**。
> **总纲：外设 = 挂在总线上的独立状态机；寄存器是 CPU 唯一能碰它的地方——遥控面板。**

## 1. 外设解剖学：每个外设都长这样

```
        AHB/APB 总线接口（01 篇的从属端口）
              │
   ┌──────────┴──────────┐
   │  寄存器组（面板）     │  控制寄存器 CRx ← CPU 写（配置）
   │  · CR 控制寄存器     │  状态寄存器 SRx → CPU 读（查询）
   │  · SR 状态寄存器     │  数据寄存器 DRx ↔ 双向（进出数据）
   │  · DR 数据寄存器     │
   └──────────┬──────────┘
              │
   ┌──────────┴──────────┐
   │  工作状态机（工人）   │  分频器、移位寄存器、计数器…
   │  ——自带动力气        │  用自己的时钟独立跑
   └──────────┬──────────┘
              │
           引脚/外部世界
```

CPU 写 CR = 下命令，读 SR = 看脸色，读写 DR = 交货取货；**中间的状态机自己干活**——CPU 写完 TDR 就走，串行化的脏活状态机包了。这个"命令-执行-回报"的三板斧就是所有外设的骨架。

## 2. GPIO：一个引脚的完整电路

GPIO（通用输入输出）= 能被寄存器控制的引脚。一个引脚背着一整套电路：

```
              VDD
               │
        ┌──────┴──────┐
 ODR ───┤ 推挽输出级    │        ┌────────────┐
        │ (P管+N管)    │──引脚──┤ 施密特触发器 ├──→ IDR（输入寄存器）
        └──────┬──────┘        └────────────┘
              GND        ↑
                   上拉/下拉电阻（可配置）
```

- **推挽输出**：输出 1 = P 管接通引脚到 VDD；输出 0 = N 管接通到 GND——两个管子"推、挽"，始终有驱动能力。注意方向：灌电流（往外拉低）比拉电流强，**LED 阴极接引脚、低电平点亮**就是用更强的灌电流（限流电阻 (3.3V−2V)/10mA ≈ 130Ω）
- **开漏输出**：只有 N 管，"1"其实是松手浮空——必须外部上拉电阻。用处：**I²C 总线靠它实现"多机共线"**（谁都能拉低、永远不会两个推挽顶牛——01 篇三态门冲突的民间解法）
- **输入侧：施密特触发器**——双阈值判 0/1（>2V 判 1，<1V 判 0，中间保持），把边沿抖动的信号整形成干净方波；上下拉电阻给"悬空引脚"一个确定的默认值（否则读进来全是噪声）
- 寄存器：MODER（方向：输入/输出/复用/模拟）、ODR（输出值）、IDR（输入值）。**读 ODR 得到你配置的值，读 IDR 得到引脚实际的电平**——开漏+上拉时两者可以不同（配置 1 但被别人拉低了）

## 3. UART：把字节钉成电平

UART（串口）= 没有时钟线的异步串行。发送方把字节**按位撕开、按约定节奏发出**；接收方**自己数拍子**拼回来。

### 3.1 帧格式与波形（发 0x41 = 'A' = 01000001，LSB 先行）

```
空闲(高) │起始│ b0 │ b1 │ … │ b7 │ 停止 │空闲(高)
─────────┐    ┌──┐   ┌──┐
         └────┘  └───┘  └────（1=高电平，0=低电平，每格=1/baud 秒）
```

- 起始位固定 0（电平从高跳低 = "我要开始了"）；停止位 1；双方只约一件事：**波特率**（115200 = 每位 8.68μs）
- 误差预算 ±2%：10 位帧累计偏差不能超过半位——02 篇"晶振 vs RC"的现实出处

### 3.2 内部流水线

```
CPU 写 DR ──→ [TDR 发送数据寄存器] ──→ [TSR 发送移位寄存器] ──→ TX 引脚（每 baud 拍移出一位）
                     │TXE=1(DR空,可收下一个)│TC=1(全发完)
RX 引脚 ──→ [过采样×16 判定起始位与每一位] ──→ [RSR 接收移位寄存器] ──→ [RDR] ──→ CPU 读 DR
                     │RXNE=1(收到一个字节,快来取)│ + 噪声/帧/溢出错误位
```

- **波特率发生器**：PCLK ÷ 分频 = 采样时钟。115200@42MHz：42M/(16×115200)≈22.78 → BRR=22+13/16，实际误差 0.07%——**一个分频器就是"约定节奏"的全部硬件**
- **过采样 ×16**：接收方用 16 倍波特率的时钟量起始位下降沿，在第 8 个采样点（位中央）判定——**容忍收发双方 ±1/16 位以内的节奏漂移**
- **TXE/RXNE/TC** 就是状态机的"脸色"：软件据此决定何时塞下一个、何时取——03 §6 的轮询程序靠它

## 4. Timer：数拍子的硬件与 PWM

定时器 = 一个自由计数的计数器 + 几个比较寄存器：

```
PCLK → 预分频 PSC ÷72 → 每拍 CNT+1 ──→ CNT == ARR？→ 溢出：置 UIF 标志 / 中断（04 篇）
                              │
                              └→ CNT < CCR 输出高，CNT ≥ CCR 输出低 → PWM 波形
```

- **ARR（自动重装）**：CNT 到顶清零重来——**溢出周期 = 72MHz/72/1000 = 1ms**（分频 72、ARR 999）：硬件定时中断的来源
- **PWM**：比较寄存器 CCR 决定翻转点 → 占空比 = CCR/(ARR+1)。**调 LED 亮度、驱动电机、产生蜂鸣——全是"计数器比分"的副产品**；关键：**PWM 在硬件里自动持续输出，CPU 一个拍都不用管**
- SysTick：CPU 核内置的 24 位倒计数定时器——专为"系统心跳"而生（05 篇的 RTOS 伏笔）

## 5. 统一洞见

**每一个外设都是同一个母题的变奏**：给状态机配一个寄存器面板。
- GPIO：状态机只有一根线，面板是 3 个寄存器
- UART：状态机是移位流水线，面板是 TDR/RDR/SR/波特率分频
- Timer：状态机是计数器，面板是 PSC/ARR/CCR
- 后面遇到的一切（SPI、I²C、ADC 的 SAR 二分搜索、USB 的协议引擎）都是这个母题的加厚版——**认识一个，认识全部**。

## 6. 轮询版 echo 程序（寄存器级，裸机）

```c
#define UART2_BASE 0x40004400UL
#define UART2_SR  (*(volatile uint32_t*)(UART2_BASE + 0x00))
#define UART2_DR  (*(volatile uint32_t*)(UART2_BASE + 0x04))

void uart_echo(void) {
    for (;;) {
        while (!(UART2_SR & (1 << 5))) ;   // 等 RXNE：收到字节（轮询状态机脸色）
        UART2_DR = UART2_DR;               // 读出再写回 = echo（写 DR 触发发送）
        while (!(UART2_SR & (1 << 7))) ;   // 等 TC：确保发完再收下一个
    }
}
```

- `volatile`：告诉编译器"这两次读 DR 不是重复读优化掉"——**SR/DR 每次读都可能不同，这是 MMIO 与普通内存的唯一软件区别**
- 这 10 行是一台能对话的机器。**但它把 CPU 100% 烧在 while 空转上**——04 篇的中断与 DMA 就是来解放它的

## 7. 本篇结论

1. **外设 = 独立状态机 + 寄存器面板**；CPU 只碰面板，脏活状态机自带动力。
2. GPIO 一个引脚 = 推挽/开漏输出级 + 施密特触发器 + 上下拉 + 三类寄存器；ODR 与 IDR 的差别是"配置"与"现实"的差别。
3. UART 的全部魔法 = 波特率分频器（约节奏）+ 移位寄存器（撕字节/拼字节）+ 过采样（容忍漂移）；TXE/RXNE 是状态机与软件的握手语言。
4. Timer 数拍子产生定时中断与 PWM——PWM 证明"状态机自治"的价值：CPU 写完就走。
5. `volatile` 是软件世界对 MMIO 的唯一请求：**别把我的寄存器读优化掉**。
