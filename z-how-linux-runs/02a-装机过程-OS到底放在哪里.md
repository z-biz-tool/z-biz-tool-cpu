# 02a · 装机过程：OS 到底放在哪里，为什么拔了 U 盘它还在（彻底版）

> 感知困惑：U 盘插上引导、装 OS，之后 U 盘拔掉，OS 却"一直在"。
> 本篇把这个过程拆到底。结论先行：**机器没有记忆，只有字节 + 规约。OS 从不"在机器里"，它只是磁盘上按规约排列好的一组字节。**
> 彻底版：拆到扇区与字节布局（MBR 的 446/64/2 结构、分区表项内容），安装器六步每步落到"写了哪些字节"。

## 0. 先做一个思想实验：拔掉硬盘再开机

机器会做什么？——卡在固件界面，提示找不到可启动设备。它什么都不"记得"。

因为开机逻辑（01a 的六环链）每次都是**冷启动重演**：

```
固件在固定地址醒来 → 按 boot order 找仓库 → 读货、验签、搬进内存 → RIP 指过去
```

这条链里没有一步是"记忆"——甚至 BIOS 的启动顺序也不是记忆，是存在 NVRAM（非易失存储器，memory_work 02：断电保留的字节）里的一张表。**"记得"这个词在硬件世界里不存在，存在的只是"读到了什么字节"**。

所谓"装了 OS"，唯一含义是：**这块硬盘上的字节排列方式，让链条的每一环都能找到下一环。**

## 1. 装机前后，同一条六环链走了三次

| 阶段 | 仓库在哪 | 链条起点 | 结果 |
|---|---|---|---|
| 装机前（引导 U 盘） | U 盘 | BIOS 选中 U 盘 | live 系统跑在**内存**里 |
| 装机中 | —（live 系统往硬盘写字节） | — | 硬盘被布置成新仓库 |
| 装机后（引导硬盘） | 硬盘 | BIOS 选中硬盘 | 装好的 OS 跑起来 |

三次链完全相同（01a 的六环），唯一区别是**仓库从 U 盘换成了硬盘**。这就是"拔了 U 盘它还在"的全部秘密——不是 OS 搬进了机器的什么地方，而是接力棒换了仓库。

## 2. U 盘的真面目：一块装了完整链的小硬盘

安装 U 盘不是什么特殊设备，它就是一块按规约排好的磁盘。逐扇区看它的布局：

```
LBA 0            ：MBR —— 446 字节引导代码 + 64 字节分区表 + 0x55AA
LBA 1..2047      ：（预留，常放 GRUB 第二段或空）
分区 1（FAT32）  ：UEFI 时代的 ESP —— 内含 /EFI/BOOT/bootx64.efi
分区 2（ext4）   ：squashfs 压缩的完整 Linux（内核 + 全套用户态，几百 MB~几 GB）
```

**MBR 的 512 字节内部结构**（装机器要精确写它）：

| 偏移 | 大小 | 内容 |
|---|---|---|
| 0x000 | 446B | 引导代码（GRUB stage1：只会一件事——把自己后续部分从固定扇区搬进来） |
| 0x1BE | 4×16B | 分区表：每项 16 字节 = [活动标志, 起始 CHS, 类型, 结束 CHS, 起始 LBA(4B), 扇区数(4B)] |
| 0x1FE | 2B | 0x55 AA 签名 |

16 字节分区表项能表达的最大分区 = 2³² 扇区 = **2TB**——MBR 的天花板，GPT（每项 128 字节、64 位 LBA）因此而生。

插上开机 → BIOS 按 boot order 选中它 → 六环链走通 → **一个完整的 Linux 跑在内存里**（live 系统）。

此刻注意一个事实：**OS 此刻住在 U 盘 + 内存里，不在电脑里**。你的硬盘可能还是全空的。（live 系统怎么在"没有可写根分区"的情况下跑起来？——initramfs/内存盘：把根文件系统解压进 RAM 当盘用，memory_work 01 的 SRAM 扮演磁盘。）

## 3. 安装程序 = 一个没有任何魔法的普通程序

安装器就是跑在 live 系统里的普通进程。它做的每件事都是"往另一块磁盘写字节"，而且它用的是普通文件接口——对它来说整块硬盘就是一个文件（`/dev/sda`，"一切皆文件"的受益者，05 篇展开）。

按顺序干的六件事，每件对应引导链的一环：

| 步骤 | 干了什么 | 本质 | 服务的环节 |
|---|---|---|---|
| 1. 分区 | 在磁盘开头写**分区表**（MBR 的 64 字节表 / GPT） | 一张"行政区划表"：第几扇区到第几扇区叫 sda1/2/3 | 为后续环节提供寻址 |
| 2. 格式化（mkfs） | 往分区写文件系统元数据（超级块、空闲块位图、inode 表） | 把"裸扇区平原"变成"有目录结构的领土" | 让字节能以"文件"形式存放 |
| 3. 复制系统 | 把内核 vmlinuz、initramfs、/bin /lib 等几千个文件写进根分区 | 普通文件复制 | 环节③：仓库进货 |
| 4. 装引导器 | GRUB 第一段 446 字节写进硬盘 MBR（第 0 扇区）；其余放 /boot/grub/ | 把"入口代码"按规约摆到固件会读的位置 | 环节④：搬运者上岗 |
| 5. 写配置 | GRUB 配置文件：内核在哪、根分区是谁、init 是谁 | 给搬运者一张"货物清单" | 环节④⑤ |
| 6. 收尾 | 分区标 active（BIOS）；或写 NVRAM 启动项（UEFI） | 告诉固件"下次看这块盘" | 决定链的起点 |

第 2 步的元数据值得多看一眼——**超级块里有什么**：文件系统魔数、块大小、inode 总数、空闲块位图的位置、日志区位置。此后任何"读文件"都从超级块出发：超级块 → inode 表 → 数据块。**格式化 = 在平原上立起这套路标**；路标本身也是字节，也占扇区——文件系统是"用数据描述数据"的自举游戏。

## 4. 下次开机：链自动重走一遍

```
BIOS 醒来 → boot order 轮到硬盘
  → 硬盘第 0 扇区 = GRUB stage1（装机时写入的 446 字节）
  → GRUB 读自己的配置，从 ext4 分区里读出 /boot/vmlinuz-xxx
  → 装进内存 → RIP 指过去
  → 02 篇的内核自举：建页表 → IDT → 时钟 → 挂根分区 → init(PID 1) → 登录界面
```

**"OS 好像自动在了"的真相**：规约是全自动的。你只要把货按规约摆好，每次开机链都会自动重走。OS 一直躺在硬盘上——用 01a 的话说，"仓库的货"——只是这次每一环都找得到下一环。

## 5. OS 到底放在哪里（清单）

| 组件 | 位置（BIOS/MBR 机器） | 本质 |
|---|---|---|
| 内核本体 | 根分区 `/boot/vmlinuz-xxx` | 一个普通文件！（通常是压缩的，内核入口先自我解压） |
| initramfs | 根分区 `/boot/initrd.img-xxx` | 普通文件（自举用的临时根，04 篇提） |
| 用户态一切 | 根分区整个文件系统 | 几 GB 普通文件 |
| GRUB 第一段 | MBR 前 446 字节 | 按规约摆的入口代码 |
| GRUB 其余 | `/boot/grub/` | 普通文件 |
| 分区表 | MBR 扇区后 64 字节（或 GPT 专用区） | 一张表 |

"OS" 不是一个东西，是**分布在磁盘各处、由引导链串起来的一组字节**。

## 6. UEFI 的规约升级（不影响本质）

- 固件自己认识 FAT 文件系统 → 不再依赖 512 字节 MBR，直接读 **ESP 分区**（EFI 系统分区）里的 `bootx64.efi`
- 启动项记在主板 **NVRAM** 里（哪个盘、哪个文件、什么参数），不再靠分区 active 标志——启动项本身就是一组字节（变量名 + GUID + 文件路径）
- Secure Boot：验 .efi 的数字签名后才跳——验签环节从"0x55AA 两字节"升级成"RSA 签名"，本质仍是**固件拒收没签名（或签名不对）的货**
- 引导链相应变短：UEFI → .efi（GRUB/直接内核）→ 内核。MBR 的 2TB 天花板与"扇区 0 只有 446B 可用"的两个历史包袱一起被甩掉

本质不变：**固件把控制权交给磁盘上的代码**，只是交接方式从"读第 0 扇区"升级成"认文件系统、读指定文件"。

## 7. 归约检验

安装器全程用了什么根能力？——`open` / `write` / `close`（对 `/dev/sda` 这个"文件"）。

漂亮的自举闭环：**live OS 用"一切皆文件"的接口布置磁盘，让这块磁盘下次开机又能长出一个 OS。** 整个装机过程归约到根：读写内存 + 读写设备 + 常规指令，没有任何新硬件能力。

## 8. 本篇结论

1. **机器没有记忆**。"装了 OS" = 磁盘字节按引导规约排列好了；连"启动顺序"也只是 NVRAM 里的一张表。
2. **装机 = 用一个现成 OS（live）给另一块盘布置完整引导链**（分区表 + 文件系统 + 系统文件 + 引导器），六步各自落到具体字节。
3. **下次开机"OS 自动在了" = 规约全自动重走链**，只是仓库从 U 盘换成了硬盘。
4. 由此你能解释更多现象：重装系统 = 重排字节；GRUB 坏了机器"起不来"但 OS 文件都在 = 链断在环节④；Live CD 能救人 = 换一个临时仓库把链接通；MBR 时代的 2TB 上限 = 16 字节分区表项的 32 位 LBA 算术。
