## 1. 一句话定位

**亲手搭出一台计算机，并看懂它为什么这样运行。**

将当前数字电路沙盒建设为“可靠的仿真工具＋具有游戏体验的计算机课程”。以真实电路行为为基础，把搭建、观察、排错、解释、迁移应用连成完整学习过程。

产品由三个空间组成：
- **冒险地图**：从零开始学习，以知识路径组织关卡、提示与挑战。
- **实验工作台**：课程和自由实验共用的搭建、仿真、波形与 CPU 调试环境。
- **作品工坊**：积累项目、可复用组件、程序和实验记录。

成功不是增加更多面板，而是让用户能够回答：哪里错了、为什么错、如何验证修复，以及下次怎样独立解决。

## 4. 产品原则

1. **正确性先于装饰。** 仿真错误会直接教授错误知识，是产品阻断问题。
2. **学习不等于刷题。** 通关必须有行为证据，理解还需预测或变式验证。
3. **失败是教学事件。** 给出输入、时间、期望、实际和观察路径，而不是只有一个红叉。
4. **保护作品。** 切关、看答案、换面板和刷新不能意外覆盖已保存成果。
5. **渐进披露。** 新手只看当前需要的工具，进阶用户随时进入完整实验室。
6. **可观察而不伪装。** 未配置的 CPU 不展示虚构寄存器；未记录的历史不补造波形。
7. **本地学习诚实定位。** 浏览器判题不是防作弊考试，本地进度不是可信认证。
8. **能力逐步扩展。** 不把逻辑仿真宣传成模拟电路、芯片物理时序或功耗分析。

## 6. 关键架构选择

| 决策 | 理由 | 重评条件 |
|---|---|---|
| 保留 React、TypeScript、Vite、Zustand、Canvas2D | 利用现有实现，控制迁移规模 | 基准证明瓶颈无法通过分层和增量绘制解决 |
| 内核留在 TypeScript，移入 Web Worker | 优先解决主线程阻塞并共用测试逻辑 | 性能数据证明需要 WASM，不以猜测重写 |
| 二态为首发，严格四态单独版本 | 兼容现有关卡，先把离散语义做对 | 基础语义、课程和测试稳定后立项 |
| IndexedDB＋Dexie、Zod 输入契约 | 事务存储、迁移、严格校验 | 确认出现云同步需求后扩展适配器 |
| 本地声明式课程与判题 | 无服务器、可复现、无任意代码执行 | 正式考核必须另建服务端信任边界 |
| 暂不引入大型 monorepo 和协作框架 | 本轮为单应用，不增加无用运维与协议成本 | 多个独立应用确实需要共享发布 |

## 7. 路线与衡量

M0 可信基线 → M1 不丢成果的实验室 → M2 可玩教学切片 → M3 从门到 CPU 闭环 → M4 打磨验收。

在 2 名前端、1 名仿真工程师、1 名产品/课程人员及共享测试支持的假设下，建议 8–10 周。该周期不是现有团队承诺；人数减少时按出口条件缩小范围，不压缩正确性门禁。

本地优先记录以下学习指标，不默认上传：
- 首次实验成功率、首次可解释结果所需时间。
- 失败后修复成功率、迁移题独立完成率。
- 项目恢复成功率、保存失败率、仿真错误率。
- 不用点击数、在线时长、连续签到代替学习成效。

性能与容量均是待验收目标。当前只完成源码静态核查，没有本轮运行测试通过证据；前次检查中默认终端未找到 Node，不等于机器没有安装任何 Node 版本。
