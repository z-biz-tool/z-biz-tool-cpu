## 1. 版本与不变量

当前 [Design](../../src/core/types.ts#L48-L65) 只包含名称、根电路和子电路定义；当前 [SaveFile](../../src/core/serialize.ts#L8-L19) 包装格式和时间，不足以表达完整实验项目。

本轮新增项目外壳，保留 Design 内部结构，降低兼容风险。必须区分：
- `schemaVersion`：项目文件结构，首发新格式为 2。
- `kernelVersion`：调度与求值语义。
- `isaVersion`：Z16 编码和执行行为。
- `catalogVersion`：元件接口、参数、行为和教学成本。
- `levelRevision`：题目目标、测试、提示和评分版本。
- `revision`：用户工程编辑版本。

版本均为显式字段；不能用应用版本替代全部版本。旧尝试、组件和课程发布版本不可原位重写。

## 2. 项目文件

```ts
interface ProjectFile {
  schemaVersion: 2;
  id: string;
  title: string;
  revision: number;
  kernelVersion: string;
  isaVersion: string;
  catalogVersion: string;
  design: Design;
  assemblyFiles: Record<string, string>;
  testbenches: Testbench[];
  watchConfig: WatchConfig;
  componentLocks: ComponentLock[];
  courseContext?: { levelId: string; revision: string };
}

interface ComponentLock {
  definitionId: string;
  componentId: string;
  version: number;
  contentHash: string;
}

interface WatchConfig {
  signals: { instancePath: string[]; pinId: string; radix: "bin" | "hex" | "signed" }[];
  cpuAdapterId?: string;
  breakpoints: { sourceFile?: string; line?: number; address?: number }[];
}
```

Testbench 是与课程测试使用同一值/时间断言基础的用户测试台；不能执行 JavaScript。源码文件名仅是项目内标识，不对应任意磁盘路径。输入拒绝危险键、原型属性和非法数值；`NaN/Infinity`、负地址、无效位宽不进入内核。

快照和轨迹分开存储，导出工程默认不附带大型运行数据。需要可复现实验时，另导出包含工程、版本、输入事件和预算的实验记录；不把浏览器缓存当作永久备份。

## 3. IndexedDB 数据表（PRJ-01）

采用 Dexie 管理 schema、事务和升级；新 schema 不能依赖读旧缓存时自动清洗掉错误数据。

| 表 | 主键 / 主要字段 | 约束与用途 |
|---|---|---|
| projects | id；title、headRevision、createdAt、updatedAt | 项目目录与最新已确认版本 |
| drafts | projectId；revision、projectFile、semanticHash、savedAt | 每项目完整草稿；与目录头同事务更新 |
| attempts | id；projectId、levelId、levelRevision、designHash、frozenProjectFile、inputEvents、seed、result、assistance | 保存可重放的提交副本与实际输入，不只存哈希；不覆盖历史 |
| progress | `[courseId+levelId]`；status、medals、masteryEvidence、legacy | 从有效尝试派生摘要，不替代尝试证据 |
| components | `[componentId+version]`；interface、design、tests、hash | 已发布版本不可变 |
| settings | key；value | 引导、显示、声音、无障碍偏好 |
| migrationBackups | sourceKey；raw、checksum、migrationVersion、status | 原样保存旧数据和迁移状态 |

调试运行数据首发保存在有预算的内存存储；用户显式保存实验记录时，以 `experimentRecord` 字段保存到独立的 attempts 记录，包含冻结工程、输入、预算及版本。首发不增加未定义的附件表，不把每次波形事件同步写入 IndexedDB。尝试副本导致配额不足时提示导出和管理历史，不自动删除证据。

### 3.1 保存协议

1. 编辑事务更新内存项目 revision，并标记“待保存”。
2. 500ms debounce，连续操作最长 2s 触发保存；操作结束可主动 flush。
3. 事务读取当前 headRevision，核对预期版本，写 drafts 与 projects。
4. 事务成功且保存 revision 等于当前 revision，显示“本地已保存”；否则继续显示待保存。
5. 存储配额、权限或事务失败显示常驻错误；允许重试、导出副本，不报告成功。

不承诺 debounce 窗口中尚未提交的改动必定跨崩溃保留。正常切关、导入、新建前等待保存成功；若失败，用户选择导出后离开或继续留在当前项目。

### 3.2 多标签页与恢复

同项目使用 Web Locks 获取独占编辑权，BroadcastChannel 传递状态，不传递完整仿真内存。第二标签默认只读或另存副本。锁随关闭释放；浏览器不支持 Web Locks 时依然通过 IndexedDB 事务内的 headRevision 比较避免覆盖，发现冲突转为只读/副本。

不使用“localStorage 锁标记＋定时器”声称实现可靠互斥。恢复选择按 projectId 与 revision，不根据修改时间简单覆盖。

### 3.3 导入与迁移

- 先检查文件字节数，再 JSON 解析、结构校验、引用校验、预算检查和版本协商。
- 已知旧格式先写原始备份，再转换到新格式；一条源记录只能成功迁移一次，校验和识别重复导入。
- 不认识的未来版本只提示无法编辑并保留原文件；不降级猜测。
- 未知元件、无效连接或丢失子电路返回预览报告，不静默丢弃后保存为正常工程。
- 旧记录拆成独立项目，旧槽位键进入迁移来源字段。旧进度标为历史完成，不凭旧字段补授理解勋章。
- 只有新数据成功持久化后才标记迁移完成；永不自动删除旧 localStorage。
- IndexedDB 不可用时进入临时内存模式并提示导出；不能假装完成迁移或可靠自动保存。

## 4. 组件版本化（PRJ-02）

封装产物包含名称、稳定外部端口、端口方向/宽度、内部 Design、依赖锁、说明和可选测试台。新封装必须填写名称及端口说明；导入的旧封装允许以“待完善元数据”状态使用，不能阻塞旧档打开。

发布形成不可变版本。用户工程保存锁定版本及所需定义，脱离本机组件库也能打开；组件库删除只影响目录，不删除其他项目已嵌入的定义。

升级流程：比较接口 → 显示破坏性差异 → 在副本上运行该组件和使用方测试 → 用户确认 → 新工程 revision。新增版本不能自动修改现有项目。

课程元件白名单递归检查展开后的基础元件；只能包含实际可达且无循环的依赖。封装要求同时检查“定义存在、实例被使用、连到有效任务路径、满足接口”，不能以空定义计数获得勋章。

教学成本按锁定 catalog 中的成本表计算，按实际实例重复计费；可见但未接入功能网络的非 free 实例也计费，避免藏入闲置元件作弊。明确 free 的注释/探针不计成本。不显示真实面积、功耗或频率结论。

## 5. 课程内容契约（EDU-03）

```ts
interface LevelDefinition {
  id: string;
  revision: string;
  world: number;
  displayOrder: number;
  prerequisites: string[];
  objectives: { knowledgeId: string; description: string }[];
  starter: Design;
  interfaceContract: TaskInterface;
  allowedComponents: string[];
  publicTests: Testbench[];
  validationCases: Testbench[];
  hints: HintStep[];
  rubric: Rubric;
  reward: Reward;
}
```

`prerequisites` 保存直接先修知识点 ID，课程 manifest 单独定义知识节点及其有向无环依赖；`objectives` 将关卡连接到所教授知识。`displayOrder` 决定世界内推荐顺序，不承担历史进度主键职责。

TaskInterface 由作者指定稳定端口标识、方向、位宽、可修改范围、必需骨架、固定初始化内容和 CPU 观察契约。显示名称可改不等于端口主键可改；相同名称的多个元件不能让判题随机选择。

Testbench 定义 reset、输入事件、推进周期和声明式断言。断言类型首发限定 `signalEquals、memoryEquals、outputSequence、halted、noDiagnostic`，以及条件满足时的固定时间检查；不提供 eval 或任意表达式执行。数值使用受位宽验证的整数/十六进制字符串；0 值不能因 falsy 判断被忽略。

每个测试声明最大周期、事件数、运行时间、输出和内存预算。随机变式只使用内置的受控生成器 ID＋参数，记录 seed；教师导入的 JSON 无法扩展执行代码。

### 5.1 课程发布流水线

现有关卡中的构造函数属于开发工具，不进入可导入内容协议：
1. 开发阶段使用现有构建工具生成骨架和参考解答。
2. ID 生成固定种子或显式稳定 ID，避免每次构建破坏测试接口。
3. 验证先修 DAG、完整31关清单、提示层级和断言非空。
4. 固化 reference design、tests、catalog/kernel/ISA 版本。
5. 对全部参考解答和刻意错误反例运行验证。
6. 生成带 manifest 与内容哈希的 JSON 资源；课程修订发布新 revision。

哈希用于一致性校验，不等于防篡改或可信签名。首发内容随应用交付，未下载资源不可宣称离线可用。

### 5.2 判题执行顺序

1. 校验提交工程和运行预算。
2. 核对题目接口、固定位宽和预置程序，禁止用学生宽度截断期望值。
3. 递归检查元件限制与封装约束；结构不合格时不运行。
4. 冻结设计、题目版本、seed 和引擎版本。
5. 每个用例创建独立运行态，依次施加输入并检查每个断言。
6. 错误/超时/取消与答案错误分开；平台故障不计入学习失败。
7. 功能通过后才计算可选工程勋章；理解勋章依据独立迁移/预测证据。
8. 在一次数据库事务中写 attempt 和 progress，防止通过记录与奖励不同步。

控制性检查只证明题目规定的性质，不宣称数学形式验证。CPU 通关必须包含不同程序、边界及分支，不只检查单个固定输出。

### 5.3 结果和本地信任边界

结果包含 `attemptId、levelRevision、designHash、kernelVersion、isaVersion、seed、status、firstFailure、checks、cost、medals、assistance`。第一次失败包括输入、期望、实际、时间和可定位路径。

`publicTests` 用于学习展示，`validationCases` 用于变式验证；二者都可能在浏览器中被查看，不能称为隐藏评测。参考答案本地可达不构成本期安全漏洞，但必须在 UI 中清楚区分“我的作品”和“参考作品”。

用户手工修改本地文件可以改变学习记录；本期不建设防作弊系统、不签发可信成绩。未来服务端判题属于另一次平台设计。

## 6. 资源预算与隐私

| 项目 | 初始上限 | 超限行为 |
|---|---:|---|
| 导入 JSON | 10MiB | 读取/解析前拒绝，保留原文件 |
| 汇编源码 | 256KiB | 返回位置/规模诊断 |
| 子电路层级 | 16 | 展开和成本统计共用循环/深度保护 |
| 展开元件 / 连接 | 10000 / 50000 | 编译前估算和展开时双重计数 |
| 单存储器 | 65536 字 | 地址位数与数据长度一同校验 |
| 内核运行态 | 128MiB | 分配前预算拒绝，不等待 OOM |
| 调试数据 | 64MiB | 按04文档淘汰检查点，必要时暂停采集 |
| 单次课程输出 | 1MiB | 返回 RESOURCE_LIMIT，不静默截断 |

以上是待基准校准的初始策略；课程可以降低，不可以绕过产品硬上限。UI 缓存、编译索引和图形数据另需监测，不声称上述预算就是浏览器进程总内存。

学习事件只保存在本地，无登录与数据上报。原始作品和运行日志不自动发送给第三方；错误报告由用户预览并主动导出。共享电脑提供清除本地项目和记录入口，但这是后续产品功能，本次不执行任何清理。
