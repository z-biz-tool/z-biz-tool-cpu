## 0. 定位

第三本书。CPU 书已经把"单周期取指-执行"闭环搭好；存储书把"会漏的电容 + 整块擦 + 寻道旋转"翻译成拍数预算。优化书要回答一个问题：**怎么把已经做对的事做得更快**——答案是流水线、转发、分支预测。

引擎没有传播延迟与门级时序，本书用"拍数"作为延迟的离散化单位：每个流水线寄存器和每级组合逻辑各占 1 拍。性能判断 = 看一个程序走完要多少拍、以及同一硬件单位时间能吞吐多少组。

| 关 | 名称 | 核心教点 | 关键元件 |

| 关 | 名称 | 核心教点 | 关键元件 |
|---|---|---|---|
| F2-1 | 分支的代价 | 分支器 = PC+1 mux target；单条 1 拍，但流水下错的指令集已取进 | add, mux |

## 2. 实现要点（已验证）

**复用元件（无新增）：** add/sub/mux/reg/ram/cmp/not/and/or/xor/const — 都是 CPU 书已有的元件。`FAST_LEVELS` 与 `STORAGE_LEVELS` 同构：tier 6、独立数组、不破 CPU 书 31 关门禁。

**判据形态：** outputs 与 mem 检查 + 拍数预算（phase 数）。无新判据类型。

**核心坑位：**
- 测试 phase 2/3 的 inputs 必须保持稳定以让流水输出延续（不能后续 phase 把 inputs 拉 0 把结果冲掉）
- reg 默认 load=0 永不自锁；常量化 load=1 或显式接 RST
- mul 不在库中，必要时以加法链或 cmp 替代
- 2-bit 饱和计数要分清 inc 与 dec 的钳位支路——sel 直通 vs sel 取反的 muxer 选通很容易接反

## 3. 后续（F3 缓存层级、F4 多核，留档）

| 关 | 名称 | 核心教点 |
|---|---|---|
| F3-1 | 为什么加 L1 | 循环取指拍数；插 L1 后骤降 |
| F3-2 | 直接映射与冲突 | 两程序同路不同 tag → 冲突；实测 miss 率 |
| F3-3 | 组相联与替换 | 2 路组相联 vs 直接映射；同冲突下前者胜 |
| F3-4 | 写策略：写回 vs 写穿 | 选一种，验证一致性差异 |
| F4-1 | Dennard 失效 | 单核提频收益递减；改双核 |
| F4-2 | Amdahl 定律 | 80% 并行 + 20% 串行；双核加速比 |
| F4-3 | MESI 四态 | 两核改同一行，M/M/E/S 状态机 |

需要新增元件：`CACHE`（含 tag/data 双口）、`MESICOHE`（四态）、可能需要 `CLK_DIV` 或专用时钟。下次续作时立项 IMP。
