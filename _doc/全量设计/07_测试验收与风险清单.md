## 1. 验收原则

- 先保存失败证据，再修复；不能只有正向参考答案。
- 测试缺失、跳过、预算耗尽和平台异常都不是通过。
- 原有 41 个顶层检查、31 关和 7 个示例是兼容基线，不是完整质量证明。
- 课程测试、独立 ISA 参考模型和用户体验分别验收，不能用同一个实现证明自己。
- 失败报告包含版本、seed、输入、错误码和最小工程；不默认上传个人作品。
- 性能指标在固定硬件/浏览器/夹具下测量，功能正确性不能为速度让步。

## 3. 必做的性质与反例测试

### 内核和汇编

- 位宽集合：1、2、4、8、16、32；含符号边界、全1、溢出、移位边界。
- 位宽链长度：23、24、25、64、256，确保不再受旧固定轮数影响。
- 至少100个随机电路夹具，每个随机重排元件和连接100次；哈希归一化后的结果一致。
- 使用超过4000个待求值器件的无环夹具，验证不会因旧阈值被标成振荡。
- 锁存与反馈：置位、复位、保持、非法输入和退出非法输入；无法收敛要返回证据，不伪造稳定值。
- 时钟：自动分频1/2/3/64、手动边沿、同沿多寄存器、派生时钟、reset后首沿。
- 汇编/导入至少10000个受限长度异常输入；有明确墙钟超时保护和seed。
- 独立Z16模型：固定指令矩阵＋至少1000个有界随机程序；仅在retire事件比较架构状态。
- 长输出：验证1000条以上有序输出；再注入超过1MiB预算的输出，必须资源拒绝而非静默丢失。

### 存储和课程

- 旧槽位、裸Design、未知版本、损坏JSON、配额失败、半途关闭迁移分别有黄金样本。
- 两标签同时保存同一headRevision时，最多一个成为新头；另一方收到冲突，不覆盖成功版本。
- 更换组件库版本后，旧项目输出和依赖哈希不变化。
- 测试目标位宽为8而学生改成1，必须接口失败，不允许将期望值截断到1位后通过。
- 参考解答未下载或生成失败时显示内容错误，不把空数组判为全部成功。
- 相同seed、题目revision、设计hash和引擎版本，判题得到一致结果。
- 自由文本解释只保存展示，不能被无模型的规则伪装成语义理解评分；理解勋章依据可判定预测/迁移证据。

## 4. 端到端黄金旅程

### 新手旅程

首次进入 → 选择序章 → 预测灯状态 → 点击输入 → 观察变化 → 完成一次连线 → 主动制造并撤销错误 → 保存 → 刷新恢复 → 进入世界一 → 测试失败 → 点击失败回放 → 修改 → 通关 → 查看组件成果。

验收关注是否无需额外口头指导完成，而不是强制用户按预定坐标点击。屏幕阅读器路径提供等价的元件/连线列表。

### 进阶旅程

自由项目 → 封装组件 → 保存版本1 → 在两个位置实例化 → 观察不同实例状态 → 编写汇编 → 明确选择存储器装载 → 绑定CPU适配 → 指令单步 → 触发观察点 → 导出 → 新环境导入并复现。

### 失败恢复旅程

存储失败常驻提示 → 导出副本 → 恢复保存；运行预算耗尽 → 查看诊断 → 修改或提高课程允许的预算；Worker异常 → 重建 → 明确显示恢复点；打开未来版本工程 → 只读说明 → 原文保留。

## 5. 性能验收方法与目标

首轮参考档：4核、8GB普通笔记本；记录实际CPU、系统、电源状态、浏览器版本。Chrome与真实Safari分别测量；Playwright WebKit结果不能完全代替Safari。

每项执行预热，再采集至少200次交互样本；长跑重复至少3轮，报告p50/p95/p99、峰值内存、错误与取消次数。后台标签降速单独测试，不与前台数据混算。

| 场景 | 目标 | 边界 |
|---|---|---|
| 1000元件/3000连线选择与拖动 | 响应p95 <50ms | 响应定义为输入到下一次正确绘制 |
| 10000元件大图编辑 | 响应p95 <100ms | 不代表可同时全速仿真；控制视口规模 |
| 仿真暂停 | Worker协作式暂停p95 <100ms | 不响应时2s内提供强制重建入口 |
| UI执行任务 | 仿真不在主线程形成>50ms长任务 | 数据解析/绘制也要单独监测 |
| 自动保存 | 500ms debounce，最长2s排队 | 成功状态必须等待事务确认，不保证故障磁盘时限 |
| 调试采集 | 64MiB上限、容量边界可见 | 不静默伪造完整历史 |
| 内核运行态 | 128MiB上限 | 不等于整个浏览器进程的内存上限 |

每个电路另报编译时间、每拍耗时、事件数量和峰值内存。若目标未达成，先测瓶颈；发布时缩小承诺容量并如实提示，不能删掉测试或把平均数替代p95。

## 6. 学习与无障碍验收

邀请至少5名未接触该产品的零基础用户完成序章观察性测试；目标为至少4人无需口头救援完成首次实验，其中位完成时间约3分钟。样本只作为首轮可用性证据，不宣称统计证明所有人都能完成。

记录失败位置、提示使用和迁移题完成情况，不默认记录摄像头或上传完整会话。教师演示可隐藏答案，但不能声称阻止用户查看本地资源。

WCAG 2.2 AA人工检查覆盖：
- 全键盘导航、可见焦点、焦点不被面板遮挡。
- 元件和连线的非画布替代，拖动的单指针非拖动替代。
- 非颜色唯一信号、对比度、字号和减少动画。
- 目标尺寸至少24×24 CSS像素或满足规范例外；常规工具目标优先32–40。
- 表单错误可读且关联字段，动态运行状态不过度打断读屏。

axe-core没有发现问题不等于无障碍完成；必须人工完成核心任务。
