# 仿真内核与调试设计

> 状态：设计方案，未实现。基线：`088b4d4`。需求：SIM-01、SIM-02、DBG-01、DBG-02。本文中的接口为拟定契约，不是当前代码导出。

[返回总览](00_总览与阅读导航.md) · [数据与版本](05_项目存储与课程数据模型.md) · [测试验收](07_测试验收与风险清单.md)

## 1. 核心分层与所有权

```text
ProjectFile / Design（不可变输入）
        ↓ 校验、层级展开、接口映射、位宽约束
CompiledCircuit（网表、依赖、稳定索引、诊断、来源映射）
        ↓ 创建独立运行实例
SimulationSession（状态、内存、时间、事件队列、预算）
        ↓ 增量事件
TraceStore / SnapshotStore / CpuDebugAdapter
        ↓ Worker 协议
UI ViewModel（只读摘要、当前观察时间、图形高亮）
```

- 设计对象不随仿真内存写入改变；“装载程序到工程初始化镜像”与“修改运行内存”分为两个显式命令。
- 编译结果可复用，运行实例不可跨项目、关卡用例或参考机共享状态。
- 所有路径包含稳定实例路径；编辑子电路定义与观察特定实例是两种不同操作。
- 编辑历史、运行回放、课程尝试是三套记录，不能用一个 undo 栈混合实现。
- `layoutRevision` 只改变坐标、视图和路径点；`designRevision` 改变拓扑或运行参数。布局编辑不重编译，运行参数变化创建新运行分支。
- `semanticHash` 覆盖拓扑、端口、参数、组件与 ISA 版本，不包含视图和纯布局；快照绑定该哈希。

## 2. 编译与诊断

编译流程固定为：输入 schema → 资源预检 → 层级引用/循环检查 → 展开 → 引脚与网络建立 → 位宽求解 → 驱动检查 → 依赖图/SCC → 来源映射。

位宽只在声明的数据端口之间传播；时钟、使能、选择信号按各自声明宽度校验，不能参与数据宽度最大值推断。采用工作队列直到不动点；未解决的约束作为诊断，不用固定 24 轮当作求解完成。

多驱动、非法端口、重复稳定 ID、未知元件、循环定义、非法位宽属于编译错误。截断默认警告；课程可将特定警告升级为阻断项。新设计优先使用显式截断、扩展组件，不能偷偷截断后仍显示绿色连线。

```ts
interface Diagnostic {
  code: string;
  severity: "info" | "warning" | "error";
  message: string;
  location?: {
    instancePath?: string[];
    pinId?: string;
    wireId?: string;
    sourceFile?: string;
    line?: number;
    column?: number;
  };
  relatedLocations?: Diagnostic["location"][];
  helpId?: string;
}
```

问题面板从结构化 code 选择解释与修复入口；不可从中文错误字符串反向推断错误类型。错误定位不到已删除对象时显示原路径，不跳到无关元件。

## 3. 首发仿真语义（SIM-01）

### 3.1 信号与位宽

- 模型：1–32 位无符号二态值；有符号仅是算术规则及显示方式，不改变底层位向量。
- 未驱动输入按兼容教学规则读零，同时保留 `driven=false`；课程可要求所有关键输入被驱动。
- 每个输出先按自身声明位宽归一化，再按显式网络转换处理；不能按宽网络保留窄输出的非法高位。
- 多驱动为编译错误，不采用“最后写入获胜”；首发不提供三态总线。
- 32 位运算避免 `1 << 32` 等 JavaScript 移位边界；所有算术边界进入独立测试。

### 3.2 时间与事件

逻辑时间使用整数 tick；内部事件顺序为 `(tick, delta, phase, stableId, sequence)`。tick 是模拟单位，首发不称其为纳秒或真实 CPU 频率。默认自动时钟每次教学单步产生一个完整高低脉冲；分频规则保留并明确显示。

一个时间点的处理过程：
1. 应用该时间点排定的外部输入和时钟边沿。
2. 对受影响组合网络执行确定性求值，记录每个提交后的网络变化。
3. 收集实际时钟输入上的边沿，对同一 delta 中触发的时序器件统一采样。
4. 将 next-state 放入暂存区；所有器件采样完毕后统一提交。
5. 传播提交引起的组合变化；派生时钟边沿进入后续 delta，重复处理。
6. 无待处理事件时结束当前时刻；再推进到下一排定事件。

同沿器件只读取提交前的网络和旧状态。器件接口拆为组合求值、时序采样、状态提交，禁止时序回调直接改其他实例或网络。零延迟 delta 用于表达逻辑因果，不是传播延迟估计。

组合 DAG 按拓扑处理；含环部分按 SCC 局部求稳定点。排序只用于确定性，不把顺序写入造成的临时值当作硬件结论。兼容锁存课程必须覆盖置位、复位、保持、非法组合以及从非法组合退出；不能因“更换调度器”静默改变教学答案。

### 3.3 时钟与存储

- 所有时钟输入边沿均由网络事件检测，包括手动时钟和派生时钟，不只扫描内置 clock 元件。
- 自动 clock 的相位、分频、前沿状态属于运行态，必须进入快照。
- 首发时序器件保持已有上升沿触发类型；未来下降沿类型通过声明扩展，不混入隐式规则。
- RAM：组合读、上升沿写；同沿其他器件采样旧输出，写提交后重新传播读输出。
- 首发无多端口冲突、字节使能或物理等待周期。ROM 的初始化加载属于工程事务；执行期间不由程序写入。
- 内存读取返回只读副本或范围分页，不能返回内核可变数组。

### 3.4 终止与预算

运行结果固定区分 `HALTED、PAUSED、COMPILE_ERROR、NON_CONVERGENT、RESOURCE_LIMIT、CANCELLED、RUNTIME_ERROR`。诊断包含阶段、元件路径、已执行次数及预算。

- 每次求值、展开、内存分配、快照、输出都参与配额。
- 超过计算预算只表示 `RESOURCE_LIMIT`；不能据此断言电路振荡。
- 对 SCC 检测到重复全状态及同等待处理事件时，报告周期重复证据并返回 `NON_CONVERGENT`。
- 任意器件异常阻止本次测试通过；不可只写日志后继续返回成功。
- 用户取消与运行故障不消耗课程“失败次数”，更不产生错误学习判断。

## 4. Web Worker 与运行会话（SIM-02）

```ts
type SimCommand =
  | "compile" | "setInput" | "step" | "run" | "pause" | "reset"
  | "snapshot" | "restore" | "subscribeTrace" | "dispose";

interface WorkerRequest {
  requestId: string;
  sessionId: string;
  designRevision: number;
  command: SimCommand;
  payload: unknown;
}

interface WorkerResponse {
  requestId: string;
  sessionId: string;
  designRevision: number;
  sequence: number;
  type: "ack" | "delta" | "result" | "error";
  payload: unknown;
}
```

实际实现用 Zod discriminated union 定义各命令 payload，禁止让 `unknown` 无校验进入内核。汇编和判题另用 `assemble/grade/cancel` 任务协议；它们不冒充仿真控制命令。

- 一次只激活一个交互运行对象；参考机/我的电路切换时保留各自会话检查点。
- 一个仿真 Worker 加一个按需创建的汇编/判题 Worker，避免在低配置设备创建无限线程。
- Worker 每最多 1000 次求值或约 8ms 结束一个批次，主动让出事件循环处理控制消息；只检查布尔标志但不让出，不能实现消息取消。
- 主线程维护 session/request/revision 和最新 sequence，拒绝旧任务响应。
- UI 增量刷新上限 30Hz；轨迹完整性独立于 UI 更新频率。暂停后必须推送最终状态。
- 轨迹数据采用 transferable 分块；转移前明确 buffer 所有权，不能让 UI 拿走仍由仿真器使用的内存。
- 协作取消目标 p95 <100ms；不响应时 2s 内提供终止并重建入口。
- Worker 崩溃恢复的是最近检查点及输入事件；若没有完整记录，只能恢复工程并重新运行，界面必须明确区别。

会话状态为 `idle → compiling → ready → running ↔ paused → halted/error`。编译时的新请求使旧编译过期；修改拓扑前暂停、冻结旧轨迹并创建新会话版本。

## 5. 波形、检查点和失败回放（DBG-01）

### 5.1 轨迹

每条记录包含 `sessionId、semanticHash、tick、delta、sequence、signalId、value、width、driven`。signalId 由编译网表映射回完整实例路径/端口，不用可变展示名称当主键。

只订阅需要的信号，初始值加变化量存储。一次 tick 内发生后恢复的脉冲也必须记录；UI 可以抽样绘制，但不得丢失底层事件并伪称完整。

功能包括信号分组、进制切换、双游标、边沿跳转、时钟参考线、断言标记、画布高亮。未来 VCD 导出单独定义 tick 与文件时间单位，不伪造物理时间。

### 5.2 快照

快照包含网表语义哈希、内核/ISA/元件版本、tick/delta、网络值、器件状态、内存、时钟前沿、事件队列、确定性随机种子状态、输入事件游标与输出序号。

首发使用深拷贝＋TypedArray 内存副本。每 100 拍或运行边界建立检查点，最多保留 100 个；后续按测量结果再引入页级写时复制，避免过早增加复杂性。

调试数据总预算 64MiB，由轨迹和检查点共同使用，包含索引及重放所需输入日志。优先淘汰最旧检查点并移动可回放起点；仍超限时暂停采集并提示。不得出现“轨迹仍可见，但入口声称可从已丢失检查点恢复”的情况。内核运行态另限 128MiB，不与 64MiB 调试预算混为一谈。

### 5.3 历史浏览与继续运行

- 浏览历史只更新只读观察视图，不污染当前运行实例。
- 点击“从这里继续”时，寻找最近可用检查点并重放输入到目标事件，验证版本/哈希，再创建新的运行分支。
- 版本不一致时拒绝恢复，允许只读看历史或从工程初始状态重新运行。
- 课程失败回放使用该次尝试的冻结设计、题目版本、seed 和输入；不能拿修改后的当前设计解释上一次失败。
- 默认定位首次断言偏差，不保证自动证明根因；提示措辞使用“建议检查”，避免把启发式定位冒充证明。

日志使用单调序号，显示列表可窗口化，判题输出必须完整保留在预算内。输出超过课程上限即 `RESOURCE_LIMIT`，不能截断后比较并获得通过。

## 6. Z16 与当前 CPU 调试（DBG-02）

### 6.1 ISA 版本

将编码格式、立即数字数、寄存器、标志写掩码、非法编码和指令说明作为统一规格来源。汇编器和反汇编器共享元数据；参考电路、独立解释器分别实现行为并接受差分验证。

针对已发现的逻辑指令标志位差异，新语义明确 AND/OR/XOR/NOT 更新 Z/N、保留 C，并发布新 ISA 标识；旧设计标记 legacy 行为。其他指令逐项固定真值/标志规范，不在运行时猜测版本。

旧版本兼容不意味着保留卡死、越界或导入漏洞。安全限制对所有版本生效；无法安全重现的旧项目只读打开并给出升级诊断。旧语义与新语义共用版本路由和测试，不能用“最新内核”静默重判旧记录。

### 6.2 适配器与步进

```ts
interface CpuDebugAdapter {
  id: string;
  isaVersion: string;
  binding: {
    pc: SignalRef;
    ir: SignalRef;
    registers: SignalRef[];
    flags: Record<string, SignalRef>;
    retire: SignalRef;
    halted: SignalRef;
    memoryInstancePath: string[];
  };
}
```

SignalRef 使用稳定实例路径＋端口。首发适配器为声明式映射，不允许导入任意 JavaScript。参考 CPU 内置映射，用户 CPU 通过向导绑定并校验类型、位宽和存在性。

- 微拍单步推进一个教学时钟周期；指令单步运行至下一 `retire` 事件，受周期上限保护。
- PC 断点在下一指令开始前暂停；内存观察点在提交写入后暂停，展示地址、旧值、新值和所属指令。
- 程序装载必须选择初始化镜像/运行实例和目标存储器；超出地址范围拒绝，不静默丢弃尾部机器码。
- 源码行到机器码地址使用汇编 listing 映射；无源码的机器码仍可反汇编调试。
- 独立解释参考模型与电路按 retire 事件比较架构状态，而非逐拍比较内部信号。
- 首次分歧输出指令地址、指令、预期/实际寄存器或写内存事件，再链接到对应微拍波形。

## 7. 关键验收

AT-03：同沿与派生沿正确、顺序重排结果一致、错误与预算分类准确。

AT-04：至少 1000 组快照恢复重放一致；旧快照不被后续 RAM 写入改变。

AT-07：取消及时、旧版本响应无效、Worker 崩溃可恢复或明确降级。

AT-08：短脉冲被记录、失败回放使用冻结输入、容量截断有提示。

AT-10：全部 Z16 指令与分支、标志边界、程序装载、多于 400 条输出及独立模型差分通过。

完整场景和目标见[测试验收](07_测试验收与风险清单.md)。本轮不实施四态、物理延迟、FPGA 或 ISA 扩张。
