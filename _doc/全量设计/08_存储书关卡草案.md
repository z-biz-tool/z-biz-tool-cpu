# 08 · 存储书《囚禁电荷》关卡序列草案

> 状态：草案（待评审）· 2026-09-23
> 内容母本：`z-how-linux-runs/memory_work/` 六篇（00 总纲、01 SRAM/DRAM、02 浮栅、03 SSD、04 磁盘、05 金字塔）

## 0. 定位与衔接

| 项 | 值 |
|---|---|
| 书号 | `book-memory` |
| 先修 | CPU 书第一层（非门）+ 第二层（译码器/分配器/多路选择器） |
| 毕业产物 | `DRAM 控制器`、`FTL 盘` 封装 —— 机器书（mini_machine）原始件；可反哺 CPU 书第五层「存储扩展与片选」作为自定义元件 |
| 原始件地板 | 门级（复用 CPU 书元件）+ 5 个介质元件，**不引入连续量仿真** |

核心思路：物理约束全部翻译成**资源/时间预算**（拍数、成本、配额），全部落在既有判题三件套上 —— 信号断言、`maxTicks` 时间预算、结构/元件限制。

## 1. 新原始件（5 个 CompDef）

| 元件 | 引脚 | 内部状态 `s` | 参数 | 对应物理（笔记出处） |
|---|---|---|---|---|
| `CAPCELL` 电容位元 | EN(字线)、BL(位线) | charge ∈ {0,1,2} | `leakN` 漏电周期 | 1T1C；半电平 VDD/2 用 2-bit 值 1 表示（01 §2.3 电荷共享） |
| `SENSEAMP` 感应放大器 | BL、SE | — | — | 抓半电平拉满幅并回写，解决破坏性读（01 §2.3） |
| `REFCTRL` 刷新控制器 | CLK、行地址出 | 轮询行号 | `window` 刷新窗口 | 64ms / 8192 行的离散化（01 §2.2） |
| `FGCELL` 浮栅单元 | PROG、ERASE(块) | bit、peCount | `programTicks`、`peLimit` | 写慢、整块擦、P/E 寿命（02 篇） |
| `PLATTER` 盘面 | STEP、RD | headTrack、rot = tick % sectors | `tracks`、`sectors` | 寻道 + 旋转延迟（04 篇） |

说明：半电平表示法沿用引脚数值位宽（值是 number），2-bit 编码 0/VDD/2/VDD，无需改内核；ACT/READ/PRE **命令译码器不做成元件**，它本身是 M2-5 的关卡目标（复用 CPU 书组合逻辑技能）。

## 2. 关卡序列（6 世界 19 关，含 3 勋章关）

### 世界 M1 存就是状态（00 总纲 + 01 §1）

| 关 | 名称 | 玩法 | 判题 |
|---|---|---|---|
| M1-1 | 两个非门锁住一位 | 用 CPU 书元件交叉耦合搭 1 位 SRAM | 写→保持 32 拍→读回；理解勋章变体：RST 后读（易失性） |
| M1-2 | 4×4 阵列与译码 | 行列地址复用译码器/分配器读写 4 个 nibble | `outputSequence` 按地址序读出；工程勋章 `maxCost` |

### 世界 M2 囚禁电荷（01 §2-3，本书核心）

| 关 | 名称 | 玩法 | 判题 |
|---|---|---|---|
| M2-1 | 会漏的电容 | 写满→等→读。用例 A：16 拍读 ✓；用例 B：64 拍读断言满电平，**必失败** —— 逼玩家发现"唯一办法是再写一遍" | 两个 TestbenchCase 对比；刷新动机的发现式学习 |
| M2-2 | 读即毁 | 读必须经 SENSEAMP（`requiredDefs` 结构检查），读后数据仍在（回写） | 结构断言 + `signalEquals` |
| M2-3 | 刷新调度 | 8 位元 + REFCTRL，每 32 拍轮询一行 | `maxTicks=512` 后 8 位全对；`maxCost` 禁止一位一根常刷线 |
| M2-4 | 命令译码：ACT/READ/PRE | 玩家自搭命令译码器；换行必须 PRE | 行命中序列 60 拍 vs 全冲突 100 拍 —— 双预算对比 = 激活税（01 §3.3） |
| M2-4b | ★ 汉明 SECDED | 用异或门搭 Hamming(7,4)，预置故障元件注入单比特翻转（seed） | 纠错后输出正确；理解勋章：双位错检出（01 §7.2） |

### 世界 M3 厚墙十年（02 浮栅）

| 关 | 名称 | 玩法 | 判题 |
|---|---|---|---|
| M3-1 | 写慢读快 | 编程需 `programTicks`=8 拍脉冲 | 脉冲不足位不变；读序列正确 |
| M3-2 | 擦是整块的 | 改 1 位必须先整块擦（NOR/NAND 分家） | 块内其余位变 1（`memoryEquals`） |
| M3-3 | ★ 寿命配额 | peLimit=100，总写入 500 次 | 任何块 `peCount` 超限判负 —— 逼出磨损均衡 |

### 世界 M4 盒子里的计算机（03 FTL）

| 关 | 名称 | 玩法 | 判题 |
|---|---|---|---|
| M4-1 | 逻辑≠物理 | 用已有 RAM 元件搭映射表，写只能去新页 | 读序对 + 映射表变化断言（禁原地写） |
| M4-2 | 写放大演算 | 完成指定写序列 | `maxTicks` 预算卡在写放大 ≤ 1.5 的实现上 |

### 世界 M5 机械的舞蹈（04 磁盘）

| 关 | 名称 | 玩法 | 判题 |
|---|---|---|---|
| M5-1 | 寻道与旋转 | 给定访问序列，每个扇区必须在转到磁头下方那一拍被读出 | `outputSequence` + 严格 `maxTicks` |
| M5-2 | ★ 电梯调度 | 请求队列预置在 RAM，实现 SCAN/SSTF | 总拍数 ≤ 电梯版预算（随机服务必超） |
| M5-3 | 顺序 vs 随机 | 同 16 扇区两种布局，两组用例对比 | 随机组预算宽 10 倍 —— 数字体感"顺序 IO 快百倍" |

### 世界 M6 金字塔（05，毕业世界）

| 关 | 名称 | 玩法 | 判题 |
|---|---|---|---|
| M6-1 | 三层书架 | 寄存器 1 拍 / SRAM 4 拍 / DRAM 16 拍(会漏) / 盘 64 拍；给定 trace 摆放数据 | 总拍数 ≤ 预算 —— 自发把热数据放上层 |
| M6-2 | 局部性演算 | 90% vs 50% 命中率两组 trace | 预算差 8 倍，对应平均访问时间公式（05 §2） |
| M6-3 | OS 搬运公司（毕业） | page cache + 脏页阈值回写 + fsync 语义 | 掉电用例：RST 后只有已回写页存活（`memoryEquals`）—— 复制品与权威（05 §3-5） |

（★ = 勋章关：`engineering` 走 `maxCost`/结构规则，`mastery` 走 `variantCaseIds` 变体用例。）

## 4. 引擎侧最小工作

1. **书架首页**：书级 manifest 列表 + 书选择屏；`buildCatalog` 现在硬校验"五世界数量固定"，需参数化为每书世界数（31 ID 唯一/先修 DAG 校验逻辑复用）
2. **每书元件目录 scoping**：左栏元件库按书过滤，挂 M1 schema 的 `catalogVersion`（否则电容位元/磁头臂会污染 CPU 关卡的 26 元件目录）
3. **5 个新 CompDef**：纯 `eval`/`onRise` + `s` 状态 + `params`，与现有元件同构
4. **判题零新增**

## 5. 设计原则

1. **先撞墙再给对策**：刷新（M2-1）、回写（M2-2）、磨损均衡（M3-3）都是先给必失败用例，让玩家自己发现机制动机 —— 对应笔记"归约法：卡住的地方就是要细读的地方"。
2. **物理 = 预算**：所有介质差异（100× 延迟、64ms 刷新、顺序/随机）翻译成拍数/成本/配额的硬预算，不引入连续仿真。
3. **上本书的产物是下本书的原始件**：CPU 书译码器 → 存储书阵列；存储书毕业封装 → 机器书总线/DMA。
